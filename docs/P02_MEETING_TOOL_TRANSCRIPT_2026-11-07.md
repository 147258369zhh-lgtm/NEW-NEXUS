# P02 会议真实工具轨迹接线（2026-11-07）

这是原 P02.1 的继续，不新增批次。上一组共同时间线已经具备工作过程展示通道，但会议 Runtime 仍只记录无障碍等待，工具开始/结束事件被丢弃。本组连接实际本地/IPC 执行边界、Room 轨迹、共同投影和现有工具卡片。

## 执行和展示

- MeetingRuntime 的本地执行改经 MeetingExecutionTranscript，实际调用仍为 AgentExecutionPort；回调只把等待、本地工具、托管工具事件入队，单 IO writer 按收到顺序写入，主线程不写 Room，不改变模型或工具执行结果。
- 工具开始/结束共享一个稳定消息 ID，来源由运行 ID、模型轮次、调用 ID 和本地/托管类型组成并做长度区分及散列；不同成员/运行/模型轮次不会串卡。本地和托管工具即使 provider 调用 ID 一样也独立。
- 每张卡保留原 sort_index、时间和作者，完成更新原位置；最新类型化阶段进入共同 ToolActivityMessageUi/AgentWorkProcess。成员/主持身份取该条历史数据和当时来源，不拿另一成员当前任务状态装饰旧卡；运行分组不会跨成员合并。
- 正常收尾在不可取消上下文中等待 writer，冲刷上限 10 秒；超时会记失败并取消 writer，不能把超时或未解决的写入错误算成已落盘。失败的最新终态最多再写一次，只重试存储快照，不重放工具；各断线阶段分别保留重试状态，后来的断线不会掩盖前一阶段的写入失败。
- 状态区分进行中、明确成功、明确失败、结果未知。旧 Runtime 缺少 success 且摘要没有明确失败时保持未知，不假定成功。未收到结束的工具在正常收尾/取消时记为中断；进程重启恢复也在原位置终结，不能因此重放手机操作。
- 旧轮次、已结束任务或停止房间里的遗留运行标记显示未知，避免永久动画。损坏、未知版本、ID 不匹配或别的房间的元数据退回原可读正文，不猜正文字符串来识别工具状态。

## 数据、隐私和备份

- 工具消息正文保存可读摘要，类型化小记录放在现有 meeting_events，最新阶段查询扩展到工具与等待两类；无数据库版本或表结构升级。开始/结束是有意义的生命周期记录，不写每个参数增量、图片字节或嵌套 subagent 进度 JSON。
- 复用敏感工具策略：MCP/个人数据等工具的原始参数、命令和结果不进入新轨迹；普通轨迹预览先隐藏命令赋值、凭据参数、认证头、JSON 密钥及 Bearer，再限制长度并标明省略。新类型化投影在读取时也应用同样策略。
- 会话 Markdown 直接导出可读消息，不会把内部 JSON 作为正文；这些系统轨迹不会被 MeetingContextHistory 当成下一轮用户或助手正文，参与者独立模型上下文沿现有路径保存。
- 完整加密归档包含原会议数据库，因此工具历史及最新阶段可在导出、暂存和启动恢复后继续呈现；逻辑聊天 JSON 没有因此扩展为会议迁移格式。

## 验证与边界

专项覆盖慢数据库回调、单 writer 顺序、去重、迟到事件、本地/托管同 ID、持久化失败、取消和有界收尾；真实 Room 回归覆盖原位置更新、历史作者/分组、恢复、删除、未知结果、敏感字段、可读 Markdown 和真实执行包装器异常/取消。完整加密备份回归检查恢复后的消息、事件和共同工具投影。

本组没有接完会议文本/思考流式事件：原始工具参数增量和嵌套进度 JSON 的排除是有意的数据边界，文本流式仍是下一步开发。远程 A2A 分支没有本地 Runtime 工具事件，本组不把它包装成已有逐步轨迹。附件入口/草稿、导航/管理一致性、拖分组和独立控制通道仍待继续，P02 不勾成整批完成。

UI 沿用上一组共同消息署名、工作过程和工具节点，没有新页面或新视觉体系；未做真机、ColorOS/Root/OTA、TalkBack、横屏/分屏验收。
