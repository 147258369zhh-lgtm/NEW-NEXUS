# P14 会话分支、来源与分支图

本次在普通会话和角色会话中落地真实分支。用户消息长按菜单、最终回复工具栏提供“从这里创建分支”；首页溢出菜单提供“会话分支”。创建后打开独立会话，不自动调用模型、重跑工具或复制原运行控制。此记录是 P14.4/P14.5 的开发进展，不代表 P14 或任意两个原批次已全部完成。后续已补项目/文件夹/上下文设置继承、失败恢复和标题搜索，详见 [设置继承记录](P14_BRANCH_SETTINGS_2026-11-07.md)；当前主库 v26、扩展库 v5、项目库 v2、逻辑 JSON schema v6。

## 存储与一致性

- 主库 `eta.db` 升为 v25，显式 v24→v25 新增 `conversation_branches` 与 `conversation_message_origins`；旧会话、消息和检查点不重建。迁移清单同步 v25。
- 分支家族 ID 固定，当前父会话和永久来源身份分别保存。删除父会话只把当前父关系置空，后代保留原家族与原分叉消息身份，不伪造祖父连接。删除子会话清理自身消息和来源；编辑后缀时保留仍存在的消息来源。
- 所有复制消息均重新分配 UUID，模型历史 ID、角色消息关联与工具调用 ID 一起重映射。保留已保存附件引用、模型选择和角色配置，清除原运行、排队发送、草稿、待重写、模型用量和临时状态。
- UI 先把新会话与待写分支纳入保存快照，现有串行保存器在同一个 Room 事务写会话、消息、完整检查点和分支来源。不能另行插入数据库再更新 UI，否则旧快照会删除新会话。
- 保存基线只在事务成功后推进。待写草稿成功后移除；失败仍可补写，不把未成功保存报告为完成；备份导入重载清除旧待写草稿。旧草稿不覆盖已经保存的节点或恢复已删除的父会话。

## 历史边界

- 创建前先等待当前保存，再读取真实持久消息和 sort_index，在提交前核对源会话仍存在、未运行/压缩/编辑且历史未改变。读取和计划计算在后台执行；阶段弹窗显示保存来源、核对历史、提交分支，提交前可取消。
- 用户消息分叉截止该条用户输入；助手消息只允许已结束的最终回复，避免从多块正文或工具调用中间分叉。
- 优先使用完整 journal，按稳定用户 ID 对齐；缺 ID 的旧记录还必须核对正文。保留真实闭合工具调用/结果，不带分叉点以后的轮次，也不复制包含未来内容的摘要。未闭合或非法工具批次拒绝创建。
- 缺失、已摘要化或无法精确对齐的旧历史，显式标记 `visible_reconstruction`，仅由分叉点前的可见消息与原工具摘要重建，不宣称完整恢复工具历史。界面及保存结果说明此差异。
- 去除临时供应商思考块、签名和不透明状态，保留普通文本和真实工具配对。普通存档本已省略的历史模型图片不能凭分支恢复，聊天附件仍可查看。
- 当前一次复制最多 32,000 条存储消息、16 Mi 个字符单位（正文、图片 JSON 与工具摘要合计），超限停止，防止手机分叉时无限制占用内存。后续已改为只读分叉点前缀，并按真实数据库验证最终回复；总来源大小不再误占前缀预算，详见 [前缀读取记录](P14_BRANCH_PREFIX_2026-11-07.md)。超过当前前缀预算的分块持久复制仍未完成。

## 图与交互

- 图使用真实节点、连接线、层级、可折叠后代和家族切换，支持打开、删除确认、精确分叉点查看和原来源会话跳转。运行/编辑中的会话暂不允许从图中删除。
- 深层节点保留真实层数，限制视觉缩进宽度；遍历使用迭代，不因深树溢栈。循环、缺失父节点或家族错误显示诊断，并保留全部节点，不能静默丢失节点。
- 来源查看页按真实消息 ID 只读查询附近记录，不替换主聊天的分页窗口；源消息已删除时说明缺失，分支复制的历史不受影响。这避免为了定位旧消息而把主窗口换成中间页、随后增量保存误删后续消息。
- 运行关联读取实际 `conversationId` 的统计记录，展示最近三次并打开明细；不会把复制的旧用量当作新运行。状态复用现有本地化标签。
- 分支图 JSON 仅包含结构和来源身份，不含标题、消息、附件、工具参数、结果或凭据。导出上限 4,096 个节点/2 MiB，先写临时文件，再发布到 SAF 位置；一分钟时限、主动取消、失败和临时清理齐全。第三方 provider 的底层阻塞响应仍由 Android/provider 决定，失败目标可能保留部分文件。
- 页面复用 Miuix 二级骨架、卡片、字体、错误/空态、确认弹窗；操作分两行，深树不挤压中文正文。英文、简体与繁体资源完整。没有进行真机截图或 ColorOS 手感验收。

## 用户真机验证步骤（待双批安装包交付后执行）

1. 打开含用户消息、工具记录与最终回复的已结束会话，长按早期用户消息创建分支。确认新会话只到该消息，之后可以独立输入，原会话的后续消息仍完整。
2. 在原会话的早期最终回复上创建另一分支，检查复制的工具记录没有被重新执行。修改分支正文或继续聊天，确认不改变来源会话。
3. 从首页溢出菜单打开“会话分支”，检查树关系、层级、展开/收起、切换家族和当前会话。点“查看分叉点”，确认高亮实际消息，返回主聊天后后续消息不减少。
4. 从图删除来源会话，确认子分支保留且显示来源缺失；关闭并重新打开应用后，分支、来源身份和正文仍一致。运行中的会话删除按钮应禁用。
5. 用角色会话的修订候选创建分支，确认当前选择的正文、角色配置和候选保留，旧重写任务不恢复运行。确认新分支继承项目/文件夹/上下文覆盖，之后修改原会话设置不影响分支；源归档/置顶不传给分支。
6. 导出分支图 JSON，核对文件能打开且只含结构，不含会话标题或正文。分别测试取消选择、主动取消导出、不可写位置和正常成功，取消/失败不能显示成功。
7. 做一次完整备份和恢复，核对分支、消息、家族及来源；用旧备份恢复时确认不崩溃。测试创建阶段取消，确认来源会话不被改动或重跑。

## 备份与剩余项

逻辑备份 schema 升为 v5，分支和消息来源采用独立流式 section。恢复先校验所属会话、消息归属、重复、家族和循环，再事务写入；旧 v1–v4 没有分支时新表为空。完整备份继续保存主库文件，新增表也计入 core 分区，不遗漏逻辑 JSON 导出。

后续已完成创建时项目绑定、分组文件夹及上下文覆盖的继承/恢复、图标题搜索与失败操作入口，详见设置继承记录。尚未完成：会议房间分叉语义、超大历史分块复制、进一步图布局优化、真机操作与全 UI 收口。P14.1–P14.3 的会议聚合、逐 HTTP 对账、预算和长期趋势继续保持未完成状态。上文 v25/schema v5 为分支第一版的存储记录，当前版本以 v26/schema v6 为准。

测试包括真实 Room 事务失败/同 writer 重试、独立修改、删除父/子和重启、v24 升级、闭合工具批次/新身份、摘要未来泄漏、角色修订、深树/循环、JSON 新旧备份/拒绝破损恢复，以及脱敏导出大小限制。最终验证结果见 [继续开发记录](DEVELOPMENT_CONTINUATION_2026-11-07.md)。
