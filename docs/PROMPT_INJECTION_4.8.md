# Eta 4.8 提示词注入

## 设计原则

提示词注入由两个独立部分组成：

1. **提示词模板**保存身份、工作方式、输出规则和历史后置提醒。
2. **作用域绑定**决定模板在哪些模型请求中生效。

同一个模板可以同时绑定多个作用域。每个具体作用域只保留一个当前模板；重新绑定会替换该作用域原先的模板。一次请求命中多个范围时，不同范围对应的模板按固定顺序叠加；同一模板命中多个范围时只注入一次。

可绑定范围：

- 全局普通运行
- 精确的提供商与模型，例如某个 DeepSeek Flash 配置
- 指定普通会话
- 指定子 Agent
- 指定会议室
- 指定会议室参与者
- 指定角色
- 指定自动任务

模型作用域解决“无论哪个会话，只要使用这个模型就启用”的需求；会话、会议室、参与者和子 Agent 作用域解决“只在这个对象内启用”的需求。两类模板可以同时命中，并按固定顺序组合。

## 运行顺序

运行时先保留安全和真实工具边界，然后按以下顺序组合固定提示词：

```text
全局
→ 当前实际模型
→ 会议室
→ 角色
→ 子 Agent
→ 自动任务
→ 当前会话
→ 当前会议室参与者
```

同一模板即使同时命中多个范围，也只注入一次。主模型、备用模型和子 Agent 分别按自己实际使用的提供商与模型解析。配置在每次模型请求开始时冻结，修改不会改变已经开始的请求。

模板内容不会授予工具、文件、终端、屏幕、MCP 或 API 权限。有效工具仍然由全局权限、场景权限和本次运行限制共同求交决定。

## 导入与导出

原生 Eta JSON 导出保存模板、指令块顺序、启用状态、注入位置和作用域绑定，可以无损恢复。原生导入是“整库恢复”，确认前会明确说明将替换现有模板与绑定。Markdown、TXT、通用 JSON、小 PRO、SillyTavern 和角色卡等外部格式只追加模板，文件中的作用域绑定不会自动生效，必须回到“作用域”页面由用户明确绑定。

导入始终先解析和预览。预览会显示格式、名称、模板与块数量、字符数、来源 SHA-256，以及转换、忽略和未授权工具声明。外部工具声明只作为提示显示，导入过程不会执行文件内命令或自动配置凭据。

## 使用方式

### 让某个模型自动使用模板

1. 打开“设置 → 提示词注入”。
2. 新建或导入模板，检查实际字符数和指令块。
3. 在“作用域”中打开“模型”。
4. 选择对应提供商和模型，例如 DeepSeek Flash。
5. 回到普通会话，确认当前模型与绑定一致后发送请求。

### 只在某个会话或会议室启用

1. 在“作用域”中选择“会话”或“会议室”。
2. 选择具体对象。
3. 选择模板完成绑定。
4. 绑定页会显示当前模板和继承来源；解除后，该对象只保留全局及模型级模板。

### 给子 Agent 附加规则

在“作用域 → 子 Agent”中选择对应 Profile。附加模板只影响该子 Agent 的独立运行，同时保留其角色指令和工具范围。

### 使用历史后置提醒

把指令块位置设为“历史消息之后”。运行时会把它作为带内部标记的临时 user 角色消息，放在历史对话之后、当前用户请求之前；模型适配层不会再把它提升成系统指令。该临时消息不会写入会话 transcript 或压缩快照，因此不会逐轮重复累积。手动上下文压缩请求也不会注入提示词。导入格式中更复杂的历史深度位置会转换成后置注入并显示兼容提示。
