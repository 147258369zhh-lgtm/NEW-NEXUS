# Eta 原始需求、参考项目与实施状态总报告

> 快照日期：2026-11-06  
> 运行环境：Android / Kotlin / Jetpack Compose / Miuix / Mica  
> 发布仓库：`https://github.com/147258369zhh-lgtm/ETA-.git`  
> 本报告用途：把沟通中提出的原始要求、后续细化、参考项目、技术路线、已经落地的改造和仍未完成的工作放在同一份可验收文档中。

本报告不把“调研过”“写了方案”“代码存在”和“真机闭环通过”混为一谈。状态分为：

- **已落地**：源码、自动测试和构建可证明。
- **已实现，待真机**：代码和自动测试已完成，但最新安装包没有完成完整端到端验收。
- **部分落地**：主链路存在，但范围、完成度或产品体验没有达到最终要求。
- **未落地**：只有调研或规划，没有可交付实现。

### 1.1 主流多 Agent 方案调研结论

| 技术方案 | 调研结论 | 本项目采用方式 |
| --- | --- | --- |
| OpenAI Agents SDK | 区分 agents-as-tools 与 handoff；管理者保留最终控制 | 采用“Agent 作为工具”作为会议室主拓扑；handoff 只作为以后显式升级动作 |
| LangGraph | 支持 supervisor、network、hierarchical 和自定义状态机 | 采用 Supervisor + 自定义持久状态机，不开放无界 agent 互聊 |
| AutoGen SelectorGroupChat | 选择下一位发言者、广播和终止条件适合讨论式协作 | 借鉴主持分派和终止，但参与者不共享全部内部上下文 |
| Anthropic Orchestrator-worker | 并行适合独立研究，成本和调用量明显更高 | 只并行独立任务，并设置并发、回合和预算边界 |
| CrewAI hierarchical process | 一个 manager 负责委派 | 主持人拥有分派权，参与者仍独立完成各自的专业任务 |

最终设计是“主持人监督器 + Agent 作为工具”的受控拓扑。一个房间只有一个主持人；用户明确 `@` 时用户指令优先；参与者上下文隔离，最终由主持人汇总或等待用户指定下一轮。

## 4. 已形成的技术方案

### 4.1 模块隔离与上游同步

- 新功能尽量放入 `io.github.mangi.eta.fork.*`，并保存 `upstream-current/` 固定上游快照。
- 上游原有的会话正文、置顶和消息仍由主数据库负责；扩展数据通过稳定 conversation ID 关联。
- 双方都修改的公共接线文件需要人工三方比较，不用整目录覆盖。
- 每次同步至少执行 Kotlin 编译、受影响测试和 APK 构建，最终再执行全量回归。

### 4.2 统一执行路径

```text
普通聊天 ─┐
会议室 ───┼─> AgentExecutionService / Agent Runtime ─> Provider / Tools / A2A
定时任务 ─┤
A2A 入站 ─┘
```

- 每次运行拥有持久状态、事件、租约、取消、超时和恢复。
- 有副作用的运行不在崩溃后自动重放，需要用户明确重试。
- 普通聊天、会议室和 A2A 不各自维护互不兼容的执行器。

### 4.3 会议室拓扑

```text
用户消息
  ├─ 用户明确 @ 1 个 Agent：直接执行该 Agent
  ├─ 用户明确 @ 多个 Agent：拆分为独立任务并行执行
  └─ 未 @：主持人选择参与者并分派
          ↓
      各 Agent 独立上下文与工具边界
          ↓
      主持人汇总或等待用户指定下一轮
```

### 4.4 上下文压缩

- 按 provider 上下文窗口预留输出、工具 schema 和协议开销。
- provider 不返回 usage 时使用估算，避免永不触发。
- 历史过大时分块摘要，工具结果可以降级。
- 摘要先写入持久快照，成功后才替换活动上下文；失败保留原历史。
- 普通对话和会议室共用压缩基础，但各自拥有模型预算和快照。

### 4.5 自我学习

```text
会话证据
  -> 候选规则或技能
  -> 冲突和敏感信息检查
  -> 用户确认
  -> 事务内晋升为版本
  -> 使用反馈
  -> 可回滚
```

自动捕获不等于自动污染长期规则。永久提示词、技能和工具权限默认需要确认。
