## 2. 开发与打包方式

1. 按下列批次连续推进，每批包含多个相关任务。单个小功能完成后继续同批任务，不以导出一次 APK 作为结束点。
2. 开发期间按需做 Kotlin 编译和受影响测试；共享 Runtime、数据迁移等改动按风险扩大回归。文档、文案等低影响改动不重复跑整套测试。
3. **默认不在每个任务或每一批结束时导出 APK。** 前九批累计开发、验证和记录；第十批集中收口交付候选包。用户中途需要上机测试时，再按当时累计版本提供安装包。
4. 每批记录实际完成项、测试结果和剩余问题；只有实装并验证的条目才能勾选完成。失败修复后继续同批开发。
5. 保留现有本地修改、包名、升级路径和 Miuix/Mica 风格。提交、推送、部署服务和发布仍按用户授权范围处理，不因本计划自动执行。
6. 用户反馈的数据丢失、导出失败、无法发送、崩溃等阻断问题优先修复；修复后回到批次队列。

## 4. 各批具体任务与验收

### 第一批：聊天与会议室统一（下一批先做）

- [ ] **1.1 共享聊天主体。** 抽取共同消息列表、工具卡片、附件、运行状态和底部输入布局；普通对话与会议室通过消息投影和配置进入同一个聊天 Composable，保留参与者身份与主持摘要。
- [ ] **1.2 输入与草稿统一。** 分会话保存草稿、附件、输入焦点；会议室保留 `@` 提及、参与者选择、主持人路由，切换时不串草稿或重复发送。
- [ ] **1.3 模式与导航统一。** 侧栏/顶部切换、选中项、搜索、返回栈和归档状态同步；当前运行离开页面后仍可找到。
- [ ] **1.4 会议设置与详情统一。** 使用现有设置页的图标、分组、说明与参数校验；保留成员进程详情和默认主持人选中行为。
- [ ] **1.5 Runtime 接线回归与缺口修复。** 对普通发送、未 `@`、单 `@`、多 `@`、停止、超时、离页、断线恢复做自动场景验证；恢复不自动重放有副作用的运行。
- [ ] **1.6 会话操作一致性。** 核对共享组件内的重命名、导出、删除、归档和恢复入口，保留运行中保护；回归多级文件夹与原有置顶手势。

验收：共同主体确实被两种模式调用；导航/草稿相互隔离；错误提示和最终结果一致；既有消息、Markdown、附件、压缩和取消行为不退化。深浅色与字体尺寸的基础适配在本批处理，完整全页验收在第九批收口。

### 第二批：子 Agent、执行边界与共享基础

- [ ] **2.1 子 Agent/会议预算。** 在已有并发与超时基础上，核对并补齐单次运行、成员、房间的回合/时间/token 限额及停止传播；额度不足给出可理解的原因。
- [ ] **2.2 模型与工具能力适配。** 保留显式调用 → Profile → 全局子 Agent → 主模型的解析顺序；按模型实际能力裁剪不支持的工具参数和多模态输入，缺少能力明确失败。
- [ ] **2.3 提示词与权限边界。** Profile、目录与策略取交集；远端结果、文档、工具输出中的指令不能扩大权限。覆盖读/写/破坏性动作和无人值守任务的越权回归。
- [ ] **2.4 最小共享能力目录。** 把本地 Profile、MCP 和 A2A 的能力、可用性、认证状态与权限纳入同一查询接口，供主持人和定时任务使用；复用现有注册信息。
- [ ] **2.5 授权与待处理入口。** 归拢需要输入、重新认证、工具确认和失败处理的状态，能跳回来源运行；核对授权范围、失效和撤销，不把一个来源声称的许可继承给其他来源。
- [ ] **2.6 统一运行事件。** 统一 run/会话/房间/成员/计划的关联、模型、阶段、耗时、usage 和工具结果摘要，为后续统计与轨迹提供数据；费用和 token 估算须标明估算，未知不能伪装为零。

验收：预算终止覆盖下游任务；不越权、不重复执行；事件标识稳定且不记录凭据。能力目录和待办取自历史路线图建议，作为共享基础补齐，不另做一套独立执行器。

### 第三批：MCP 与 Skills 管理

- [ ] **3.1 MCP 连接与认证诊断。** 在现有添加、刷新、Token 更新基础上，补齐连接阶段、超时、认证过期、可恢复错误、最近检查和脱敏诊断。
- [ ] **3.2 MCP 资源/提示模板浏览。** 对服务器声明支持的 resources/prompts 提供分页、读取、大小限制和不支持提示，保留工具发现与刷新。
- [ ] **3.3 MCP 工具调试。** 展示输入 schema、参数校验、调用结果、耗时、取消和失败原因；真实工具调用遵守应用现有授权边界。
- [ ] **3.4 批量配置与权限审计。** 配置导入/导出、同名冲突预览、来源和版本信息；查看服务器对各 Profile 的可见工具和权限变化，凭据不混入普通导出。
- [ ] **3.5 Skill 完整资源编辑。** 在现有导入、启停、删除、重装基础上，增加包内目录、SKILL.md 与资源编辑、解析校验、未保存提示和原子保存；沿用安装锁与恢复日志。
- [ ] **3.6 Skill 测试工作流。** 提供可检查的测试入口、输出和失败记录；测试范围与工具权限明确，不因编辑或导入而自动执行脚本。
- [ ] **3.7 Skill 包导出与版本管理。** 可选包导出、完整资源清单、版本/来源/hash、导入差异、冲突处理及更新回退。现有 ZIP 校验、安装事务、失败回滚继续复用。
- [ ] **3.8 批量更新。** 检查已安装来源更新，展示差异并处理本地修改冲突；逐包显示结果，取消或失败不破坏可用版本。

验收：编辑 → 校验/测试 → 导出 → 再导入可还原完整资源；更新失败保留旧版；MCP 能力按服务器协商结果展示。已有安装功能只补缺口，不重写已验证的安全解包器。

### 第四批：A2A、会议室与定时任务贯通

- [ ] **4.1 局域网双向闭环。** 核对实际绑定地址、Agent Card URL 与端口、认证、任务/结果/取消；提供电脑端可复现的本地联调样例，避免依赖真实付费模型才能做协议回归。
- [ ] **4.2 一次性配对。** 短期配对码/二维码、过期和重复使用防护、设备/Agent 身份显示；保存凭据走 Keystore，不能靠“同一网段”获得信任。
- [ ] **4.3 撤销与丢失设备处理。** 对端授权列表、精确身份范围、令牌轮换/撤销、被撤销后的任务处理，保留现有手动 URL + Bearer 接入。
- [ ] **4.4 外部 A2A 会议成员。** 配置、能力检查、参与者状态、独立结果与 artifact、超时和取消接入共享会议时间线。
- [ ] **4.5 定时会议与远端任务。** 核对并补齐本地/会议室/A2A 三种目标的计划编辑、输入、输出归属、历史跳转、取消和超时；保留默认不自动重试副作用的规则。
- [ ] **4.6 离线与恢复。** 断网、认证过期、进程中断后的任务水位、待处理入口与取消未确认状态一致；已完成结果不能被旧事件覆盖。

验收：模拟对端覆盖重复投递、认证失败、轮询、取消、恢复与 artifact；用户随后验证真实手机 ↔ 电脑和外部成员联调。电脑→手机的真实网络证据单列，不用 mock 成功冒充。

### 第五批：跨网络可达与嵌入式传输

- [ ] **5.1 固定依赖与可选模块。** 以已审阅方案及固定参考版本锁定 Go/gomobile/tsnet/Headscale/NDK、AAR 来源与校验；列清许可证、包体积和平台兼容性。
- [ ] **5.2 Headscale 接入与设备生命周期。** 控制面配置、短期注册、设备身份、登录/退出、撤销和失败恢复；真实控制面部署属于外部资源，不擅自部署。
- [ ] **5.3 tsnet 数据面。** A2A 内部服务绑定回环地址，由可选传输暴露；动态生成实际 Agent Card 地址，不硬编码不存在的可达 URL。
- [ ] **5.4 双重鉴权。** 精确 peer ACL + Bearer，处理撤销、过期和丢失设备；禁止整段 tailnet 默认可信。
- [ ] **5.5 前台生命周期与网络切换。** 前台服务、断线重连、Wi-Fi/移动网络变化、VPN 共存、超时和取消；提供脱敏连接阶段诊断。
- [ ] **5.6 HTTPS 隧道回退。** 将用户自备 Termux/cloudflared 等入口整理为可检查的配置流程，与内嵌传输并存；不把手机本身描述成自动拥有公网地址。

验收：编译与模拟传输验证之外，启动耗时、体积、耗电、熄屏保活、网络切换、VPN 共存、双向调用必须由用户在设备上验证。Gate 未通过时保持可选/实验状态。外部部署或设备结果未齐时继续其他批次。

### 第六批：终端与文件工作流

- [ ] **6.1 POR/Omni 工具差异表。** 逐项核对固定参考版本的 Shell、PRoot、后台任务、文件工具与环境管理；已有能力登记为保留，实际缺口进入实现。
- [ ] **6.2 环境安装与维护。** 安装阶段进度、取消、校验、失败清理、已安装状态和升级/重装路径，保留用户数据与普通/Root 模式区分。
- [ ] **6.3 终端会话与后台任务。** 命令执行、输入输出、会话切换、进程状态、停止和重启后的恢复说明贯通；中断不自动重放可能有副作用的命令。
- [ ] **6.4 文件产物联动。** 聊天/会议产物 → 工作区 → 终端工作目录 → 预览/分享/搜索/导出形成可跳转流程，Root 与普通后端遵守相同边界。
- [ ] **6.5 平台验证补齐。** 为 Windows 跳过的 POSIX、进程树、权限、PRoot 和链接测试补 Linux 执行路径及结果记录；Android ROM/Root/PRoot 由用户验收。

验收：环境安装失败可恢复，命令停止不遗留可控子进程，文件路径和分享范围不越界；不把已经完成的跨目录搜索与文件夹导出重新列作新功能。

### 第七批：学习、自动技能与压缩评测

- [ ] **7.1 从经验生成 Skill 候选包。** 把已有候选/证据转换为可预览的技能内容与资源，复用第三批包格式；标明来源、权限和生成方式。
- [ ] **7.2 测试、确认与发布。** 候选包先验证和测试，再由应用用户确认启用；保留版本与回滚，自动捕获不等于自动获得永久权限。
- [ ] **7.3 学习效果评测。** 建立可复现且不含真实隐私的语料、基线与指标，记录成功率、误学、召回及回滚效果；真实长期反馈没有样本时标明数据不足。
- [ ] **7.4 压缩同语料对比。** 固定本项目与 POR 版本，比较质量、成本、延迟、关键事实丢失、溢出和恢复；模型费用依赖可用账号，先完成离线回归与评测工具。
- [ ] **7.5 反馈与回退接线。** 将规则/技能使用与实际运行关联，能够指出哪个版本影响结果、撤回并复测，保留 MEMORY.md、CAS、检索、pin 与原始 transcript。

验收：候选 → 测试 → 确认 → 使用 → 反馈 → 回滚可复现；评测工具完成与效果已经提升是不同结论，不预填漂亮数据。

### 第八批：统计、运行轨迹与分支图

- [ ] **8.1 统计数据层。** 使用第二批事件聚合模型/成员/房间/计划的请求、耗时、usage、工具调用、失败、重试及预算；未知/估算与真实值区分。
- [ ] **8.2 统计中心。** 时间范围、模型/Agent 筛选、消耗与成功率趋势、明细追溯和脱敏导出；可配置价格，不假设所有 provider 计费相同。
- [ ] **8.3 运行轨迹。** 以真实持久事件显示路由、成员分派、工具、压缩、失败和取消，可跳转会话/成员；恢复后顺序与终态一致。
- [ ] **8.4 会话分支数据与操作。** 先明确真实会话父子分支、分叉位置和消息归属，补创建、切换、持久化、备份与删除规则；运行事件树不能代替会话分支图。
- [ ] **8.5 可视化分支图。** 展示分叉、当前分支与关联消息，定位和跳转；不把切换分支实现成自动重跑旧工具。

验收：聚合与明细可对账；统计不泄露凭据；重启、导入备份、取消和并发更新后，轨迹与分支关系仍正确。

### 第九批：外观与 POR/Omni 展示能力

- [ ] **9.1 固定参考与产品口径。** 完成 POR/Omni 剩余功能差异矩阵，明确“灵屏”“流体云”的触发、界面、输入输出、生命周期及权限，再进入实现；名称相同不算能力等价。
- [ ] **9.2 Omni 全页覆盖。** 在现有 Classic/Omni 配置上覆盖聊天、会议、侧栏、工作区、设置及工具管理页，切换后不残留另一套样式。
- [ ] **9.3 外观细调。** 补齐聊天气泡、侧栏、输入区、工作区、材质、缩放和动画参数的预览、保存与恢复默认；兼顾纯黑和模糊降级。
- [ ] **9.4 灵屏实现。** 按 9.1 确认的参考行为完成独立入口、内容与运行状态接线、退出/失败路径及所需系统权限说明；不能以一个普通状态面板冒充完成。
- [ ] **9.5 流体云实现。** 复用统一运行状态，完成运行/等待/完成/失败显示及跳回、停止等交互；通知、Live Updates 与 ROM 不支持时提供降级。
- [ ] **9.6 统一视觉与无障碍。** 浅/深/纯黑、360/412/600dp、大字体、键盘、横竖屏、触觉、可读语义和减少动画设置逐页核对。维护期不破坏原有精细 UI。

验收：共享视觉 token；新增展示由真实事件驱动；不遮挡系统操作或重要输入。自动布局/状态证据与用户实际设备观察分别记录。

### 第十批：工程收口与集中交付

- [ ] **10.1 数据总回归。** 覆盖当前及旧版数据库、设置、文件夹、Skill/规则版本、任务、统计和分支数据迁移；保留包名和覆盖升级路径。
- [ ] **10.2 备份总回归。** 已修复的加密/非加密导出、进度、取消、完整清单、损坏归档、导入回滚，以及所有新增业务表和文件都进入完整备份验证。
- [ ] **10.3 自动质量检查。** 受影响测试 + 全量回归 + Lint，Linux 执行平台相关测试；对既有 421 警告按风险分类治理，不用数量下降代替功能验收。
- [ ] **10.4 上游维护。** 审查现有 CI 与同步脚本，完善固定基线、三方差异、冲突清单和依赖锁定；若需更新上游，先完成本地差异审查，不整目录覆盖。
- [ ] **10.5 统一候选安装包。** 全部纳入本轮范围的功能验证后集中构建、签名校验、校验和、变更说明和已知限制，交给用户做真机验收。
- [ ] **10.6 根据反馈收口。** 按用户真机结果修复阻断问题，复测受影响路径；更新状态账本，记录仍需外部环境的 Gate。发布/推送另按用户明确安排。

验收：每个完成项有对应代码/自动证据或用户真机结果；不把未验证项合并成“全部完成”。
