# 记忆自动整理与自学习完善

版本：4.7.1，versionCode 2026110708。

## 本次实现

- 新的普通会话用户消息、会议室原始用户消息进入持久整理队列。角色扮演不参与现实记忆提取；助手回复、网页、工具结果不会自动充当用户事实证据。
- 使用当前选定模型提取偏好、事实、项目决定、明确的步骤和纠错经验。提取请求没有工具权限，并要求逐字原话证据；单次最多 8 条。
- 结构化记忆包含作用域、层级、主题、内容、原话、来源、创建和修改时间、有效期、审阅状态和替代关系。
- 全局、项目、会话、会议、任务作用域分别隔离。核心、长期、项目、任务、临时、其他作为独立层级。
- 等价内容去重；相似但有差异的内容保留并提示可能冲突，避免把数字、否定、文件路径的变化误当重复。已拒绝内容不会因再次提取而重新待审。
- 记忆支持审阅前修改、确认、采用新内容替代旧内容、两条均保留、拒绝和归档。确认时重新核对冲突和版本，避免覆盖审阅期间发生的更新。
- 只有已确认且未过期的记忆可被检索或注入上下文。局部记忆默认 30 天到期；全局和项目记忆不自动到期。
- 自学习候选支持修改、确认并启用、固定、归档和版本回滚。后台在确认和晋升两个步骤之间再次验证冲突批准版本；多条冲突一并展示和确认。生效经验会进入后续任务上下文。全局经验进入自学习，项目和会话专属流程保留在对应记忆作用域。
- 记忆文档继续保留，保存和清空使用 revision 校验，防止覆盖其他会话的新修改。

## 休眠与空闲整理

此处的自学习是整理可复用记忆、经验并在后续任务中检索参考，不会训练或修改模型权重。

默认开启空闲整理，条件为充电、熄屏、非计费网络，停止任务后等待 10 分钟，每 60 分钟检查，每次最多整理 2 个来源，滚动 24 小时最多 6 次提取请求。上述条件、间隔、额度、提取类别和局部记忆有效期均可在“策略”页调整。

WorkManager 负责系统调度，Android/ColorOS 省电策略可能推迟执行，不承诺定点唤醒。“立即整理”可跳过空闲、充电和熄屏条件，但仍遵守请求额度，前台 Agent 任务优先。请求有 90 秒超时、失败重试、进程中断恢复；完成或终止失败后清除队列中的原文，超过 7 天的来源不再提交提取。

## UI

- 记忆：记忆库、文档、策略。记忆库提供搜索、状态、作用域和层级筛选、来源证据、冲突对照、最近整理状态。
- 自学习：候选、规则、策略。提供待审阅数量、搜索、处理历史、中文状态、规则版本和固定状态。
- 沿用现有 Miuix 主题、列表、分组、弹窗和字体；长内容弹窗可滚动。浅色常规屏、深色窄屏、大字体和冲突对照均有截图检查。

## 数据兼容

- 学习数据库 v1 → v2 显式迁移，只新增记忆条目与整理队列表，不删除原有候选、证据、规则、版本和反馈。
- JSON 备份 schema 7 新增结构化记忆条目，包含验证、导入和失败回滚；恢复时清除旧整理队列，并阻止已经发出的旧来源提取结果写回。完整备份包含学习数据库与相关设置。学习规则和整理队列不属于 JSON 会话备份，需使用完整备份迁移。
- 旧 Markdown 文档和结构化记忆是并行来源；此版不会自动重写手工 Markdown，也未实现两者之间的语义冲突合并。

## 验证范围

专项覆盖：并发去重、差异事实保留、作用域隔离、拒绝保持、审阅版本变化、多规则冲突替代、过期重提、原话证据、敏感字段过滤、额度统计、进程中断恢复、旧数据库迁移、备份往返与无效数据拒绝。

通过本地模拟 HTTP/SSE 服务验证提取到候选的真实 Provider 请求路径，并检查提取请求不携带工具和自定义消息覆盖。没有为验证自动提取消耗用户真实服务商额度。

Android 16/17 的数据库与记忆逻辑使用 SDK 36/37 Robolectric 测试。ColorOS 长时间熄屏、Doze、ROM 后台清理以及真实服务商的提取质量仍需真机持续使用验证。
