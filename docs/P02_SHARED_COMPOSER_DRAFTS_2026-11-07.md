# P02 共享编辑器、草稿与输入交接

日期：2026-11-07。对应原 P02.1、P02.2、P02.3、P02.5 的一组开发工作，**P02 整批仍未完成**。双批安装包节点仍为 P01–P02；当前继续开发，整批出口满足后才生成桌面包。

## 已实现的行为

- 普通聊天和会议物理使用同一个 `ConversationTextEditor`，共同字体、行距、占位、选择/光标和错误提示。共同 `ConversationStage` 使用带实体类型的身份，原始 ID 相同的聊天、会议及尚未分配 ID 的新聊天不会串编辑/滚动局部状态。两个会议入口还检查异步快照的真实房间 ID，切换时不短暂展示或发送到旧会议。
- 文本草稿写入独立私有 `eta_conversation_drafts`，包含完整空白、Unicode、光标及反向选择。单 IO 消费者依序执行读/写/清空/冲刷，编辑观察延迟 300ms 合并，离页和 ON_STOP 提交最终快照。主线程不等待同步磁盘提交。
- 迟到读取不覆盖已经输入或明确清空的文字；IME 的真实输入转换还直接登记编辑意图，覆盖同一帧先输入再删空、snapshotFlow 未观察到中间文字的情况。未完成恢复或坏记录不会因离页空框被删除。恢复/保存错误可见且可重试。最近 32 个正常条目使用缓存，待写和写入失败的快照单独保留，不会被最近缓存淘汰；另一会话的成功也不能掩盖当前失败。
- 同一实体从一个已挂载编辑器交到另一个时，先接过未到 300ms 的真实输入，再撤销旧编辑器的写入资格。旧页面的迟到 onDispose、旧注册句柄注销以及离开新页面都不会重新启用旧页面的写入。明确的外部分享文字优先于旧页面交接。
- 历史消息编辑使用单独输入状态，不覆盖未发送草稿；结束编辑回到原草稿。运行过程中可以继续输入下一条会议草稿，停止仍有独立 48dp 按钮；会议排队和补充通道尚未在此阶段完成。
- 会议 @ 建议按真实光标查询，选中一段文本时不弹补全。选择建议时重新读取光标/正文，只替换所在 token，保留后续正文并将光标放到补全词之后。
- 外部分享合并使用活动且已完成恢复的真实输入，不依赖过时的业务 input。页面不可见/尚未恢复时创建新会话以保护原草稿。业务 input 交给编辑器后按会话 ID、版本和原文确认一次，避免返回页面后旧分享/撤回文字覆盖更新过的草稿；迟到确认不能清掉新分享或另一会话。
- 普通发送/插话返回接收结果；加载中、压缩中、删除中、空输入、工具条件不满足及运行登记拒绝时不清输入。草稿尚未恢复或恢复失败时暂不允许发送，避免只发出附件就清掉尚未读回的文字；仍可编辑及停止任务。执行/队列接收后只清除实际提交的快照，不删除随后输入的文字。接收表示进入会话或队列，模型/网络之后仍可能失败；已展示的用户消息保留供重试。
- 普通选图补上异步归属检查，切走再切回相同会话也不会把过期读取结果插进当前附件区；保留现有文件/分享的归属检查与授权释放。

## 数据与备份边界

- 新草稿文件为版本 1 的 JSON 条目；不改变主库和会议库 schema，也不将界面草稿加入逻辑 JSON 的聊天内容。草稿位于应用私有目录，与现有本地聊天存储口径一致；不宣称单独应用层加密。
- 完整备份在扫描私有目录之前冲刷草稿队列，真实草稿 XML 随 `shared_prefs` 进入完整/加密归档和启动恢复；有未解决写入错误就不把导出当作成功。
- 逻辑 JSON 替换成功后清除本机草稿并使旧租约失效，防止导入复用 ID 时带入之前的输入。验证/事务失败时保留原草稿；提交后清理失败有已导入但草稿清理未完成的明确错误。完整归档按原重启恢复路径保留自己的草稿。
- 删除聊天先等待核心删除保存成功，再使该实体草稿失效；会议删除在真实数据库事务成功后处理。迟到旧编辑器不能复活草稿，同 ID 的另一类型实体不受影响。
- 本轮持久化范围为文字及选择，**未发送图片/文件和会议附件的完整持久恢复仍在 P02.1**。文本草稿不等同于完整附件草稿；普通聊天消息记录、队列和会议记录的既有存储语义没有被重新命名成完成。

## P02 出口补充：附件草稿与会议提交（2026-11-07）

- 普通聊天和会议共用图片/文件/文件夹选择入口；图片正文在草稿保存时转为应用私有去重文件，元数据原子写入，导入失败、写入失败和旧页面迟到不会清空当前附件。
- 草稿按 `chat`、`meeting` 和未分配新聊天身份隔离；切换、删除、逻辑导入、完整加密备份都会冲刷或使旧租约失效。完整归档包含草稿 JSON 与私有图片文件，恢复后继续显示。
- 会议用户消息将附件元数据和消息放在同一 Room 事务；参与者历史只向当前成员提供用户附件，不向其他成员泄露；工具能力不足时明确拒绝文件附件。Markdown 导出列出本地图片并提示使用完整备份迁移正文。
- 运行中的会议输入进入最多 8 条的顺序队列，当前轮结束后自动启动；停止仍优先，队列不会跨房间混用。
