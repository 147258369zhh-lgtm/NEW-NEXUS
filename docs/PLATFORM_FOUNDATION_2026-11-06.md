# P01 第一组：兼容基线与无障碍状态修复

日期：2026-11-06。用户已确认最新方案并要求开始逐项开发。本组属于 P01，不代表十六批全部完成，也不代表无障碍后台稳定性已经完成真机验证。

## 已实现的内容

### 1. 系统与运行模式快照（P01.1）

新增 `DeviceRuntimeSnapshot`，读取实际 Android release/API、厂商、型号、系统 build、应用 target API、Root 状态与可选框架连接状态。读取不执行 `su`，不申请新权限，不将 API37 或权限已授予当作“兼容通过”。

权限健康页复用现有 Miuix 页面骨架、SmallTitle/Card、字体和颜色，新增系统信息卡。普通模式与 Root 增强状态分开显示；Root 放在“可选增强”组，未 Root 不再计入权限故障数量。

### 2. 无障碍实际连接与授权状态分开（P01.2 的检测部分）

新增 `AgentAccessibilityHealth`，统一识别：

| 状态 | 判断 | 产品表现 |
| --- | --- | --- |
| 已连接 | Eta 实际持有服务实例 | 可以使用屏幕观察/动作 |
| 已授权但断开 | 系统总开关与 Eta 服务配置开启，但实例未连接 | 警告并显示重新开启指引；不再显示正常 |
| 未开启 | 系统总开关关闭或 Eta 未在服务列表中 | 显示授权入口 |
| 无法判断 | ROM 拒绝读取设置 | 显示检查入口，不崩溃或虚报可用 |

组件名通过 `ComponentName` 解析，识别完整和缩写形式，避免原有字符串比较误判。真实连接优先于可能滞后的配置读数。

服务连接、解绑和销毁更新 StateFlow；系统开关变化通过 ContentObserver 通知。页面订阅随作用域关闭并注销监听，无常驻轮询。普通权限页、设置页和能力页均同步刷新，不必退出重进。旧服务实例销毁不能把较新的连接清空；同一次解绑/销毁只计一次中断。

本进程记录最近连接/断开的单调时间、断开回调类型和次数，并记录不含用户内容的日志。`UNBOUND/DESTROYED` 只描述收到的回调，不冒充“已确定是 ColorOS 杀进程”；进程被直接终止也不能保证收到销毁回调。

GUI 入口区分 `ACCESSIBILITY_DISCONNECTED`，无可用恢复后端时直接返回具体原因，不继续坐标点击或 Shell 重放。提示词和工具错误传递已同步；既有保护后端保留有限恢复。恢复等待也检查线程中断，停止后不继续完整轮询。

**第一组历史边界：本组当时未实现独立 Root 恢复后端、未改写服务列表。后续[第二组](ROOT_ACCESSIBILITY_RECOVERY_2026-11-06.md)已补可选 Root 后端、受控重绑与有限退避，并对最后一个服务停止自动写入；不承诺无 Root 自动重启，也不代表全部自行关闭问题已经解决。**

### 3. 修复 ColorOS 后台设置入口（P01.3 的一项缺口）

原入口写死 `io.github.mangi.eta`，与工程实际安装包名不一致，并使用前台用户而非应用所属用户。现在使用 `context.packageName` 和应用 UID 所属用户，并对 shell 参数正确引用。

ColorOS 私有 Activity 在新 ROM 缺失、Root 失败或 `am` 返回 Error 时，回退系统电源管理页，再回退应用详情；全部不可用时提示用户。Android 的 `am` 可能 exit=0 但输出错误，现已单独检测。非 ColorOS 或无 Root 直接走标准设置，不为打开页面额外申请 Root。

### 4. 麦克风权限状态与入口（P01.3）

权限健康页补麦克风状态，支持申请、撤回后的刷新与应用详情入口。拒绝且系统不再允许请求时，下次进入设置处理，避免反复点击无响应；已授权可直接管理。文案明确麦克风授权不等于后台录音不受限制，没有把现有前台浮窗改称全天唤醒服务。

### 5. 保留现有功能与数据

没有变更包名、数据库版本、备份格式、文件夹结构或模型配置，没有提交/推送，没有生成 APK。此前备份/文件夹/Runtime 改动保留。本轮测试仅编译应用和测试所需类/资源，不执行安装包导出任务。

| Android17 LAN | 已有权限、健康页和 A2A 申请入口；第三组补共享 HTTP 诊断和模型停止无效重试 | 普通域名私网归因、原生/入站链路及设备网络切换验证，见第三组审计 |

原生检查仅说明静态 ELF 布局符合对齐条件；并不证明 PRoot 的所有系统调用、后台运行和新 ROM 加载已经验证。

## 用户以后拿到累计版本时的检查步骤

这不是要求现在安装或重新打包；保留到用户需要累计测试版本时执行。

1. 权限健康页核对 Android/API、型号/build 与普通/Root 模式；无 Root 时不应仅因 Root 未授权就显示故障。
2. 开启 Eta 无障碍并回到应用，观察已连接；在服务没有实际绑定时应显示警告，不应因开关开启而显示正常。
3. 应用保持打开时关闭/开启系统无障碍，检查权限页、设置页和能力状态更新；断开时屏幕操作应明确失败，不能改走盲点坐标。
4. 开启其他无障碍服务并重复步骤；本组没有写服务列表，不应改变其他服务配置。
5. 在 ColorOS 分别以普通/Root 模式打开后台设置，确认目标是当前 Eta；私有入口失效时检查是否回退标准页。多用户环境核对当前 Eta 所属用户。
6. 申请/拒绝/撤回麦克风并返回，检查状态刷新、再次进入设置；文字聊天应正常。
7. 升到 Android17 后重复上述步骤并记录完整 build；LAN 连接分别检查未授权、授权和撤回。全功能/OTA 结果继续按最新总计划登记。
