# P01 朗读前台服务与 MCP 凭据兼容补齐

日期：2026-11-07。接续[兼容审计](PLATFORM_NETWORK_AUDIO_AUDIT_2026-11-06.md)，完成两项已确认的源码缺口；设备、锁屏、OTA 和实际系统资格仍由用户验证。

## 朗读启动必须等到服务真正进入前台

原先 `ReadAloudPlaybackService.start()` 只发送启动 Intent，控制器立即申请音频焦点；异步 `startForeground` 被拒时仅写日志，播放器不知道服务未就绪。在 Android16/17 的后台音频限制下，这种顺序不能保证播放资格。

- `start()` 现在挂起等待所属会话的成功确认，最多五秒。只有 `startForeground` 成功后，控制器才申请焦点、创建音轨和请求合成。同步启动被拒、异步提升被拒及等待超时通过现有朗读错误入口呈现英/简/繁提示。
- 等待前登记释放责任；停止、换消息、抢占音频或宿主取消均结束 pending 请求。外层调用超时保持取消语义，不误转成本地启动超时；迟到确认不继续合成或播放。
- 服务返回按会话关闭的句柄；旧句柄和旧通知的停止操作不能结束新会话。服务销毁会打断所属播放。取消后的启动 Intent 若迟到，仍先满足系统前台启动要求，再及时退出，避免留下空服务。
- `SpeechAudioLease` 在同步前置回调后再次核对所有者，防止回调中发生停止/替换后仍申请焦点。浮窗播放沿用现有服务提升接口，复用控制器的等待与清理顺序。

没有新增全天监听、后台麦克风豁免或唤醒引擎；连续对话仍在 P02.5/P06。通过模拟服务确认不等于 Android/ColorOS 已实际授予前台资格。

## MCP 凭据失效必须可见、可恢复

原先解密失败返回 null，与从未填写混淆；更新、删除服务器还会先读取旧明文，直接改成抛错会反而阻断重新填写和删除。

- 分为缺失、可用、无法解密三种状态。失效密文、丢失设备密钥或密文被修改均产生独立 `McpCredentialsUnavailable`，不带原始凭据或底层异常；读取绝不自动生成替代密钥。
- 标记需要 Bearer 认证的服务器即使没有已存令牌也明确失败，刷新/资源/模板在发网络请求前给出重填入口说明；无认证服务器忽略遗留密文。运行目录只排除凭据不可用的服务器，不拖垮其他服务器和本地聊天，也不将失效服务器的工具送给模型。
- 设置页在 IO 线程检查真实凭据状态，显示“正在检查 / 已配置 / 缺失 / 无法解密”；保留原 Miuix 设置行和令牌入口。保存期间阻止重复提交，成功才关闭；失败保留当前输入和具体错误，取消/关闭清空令牌。
- 跨存储失败回滚使用旧密文快照，无需解密。修改其他设置不会读取旧令牌；取消认证、删除、重填不被损坏的旧令牌卡住。实际 Room 的拒写/拒删 trigger 验证旧密文及原服务器仍可恢复。
- 完整备份继续保留既有“备份其他数据、跳过不可读的可迁移明文”策略，对 MCP 加入独立计数诊断，避免新失效异常使完整备份整体失败。没有把不可读凭据称为已成功迁移；面向用户的迁移警告和设备恢复仍在 P16。

测试通过可注入 JCE AES 密钥模拟设备密钥丢失/替换及 GCM 验证失败；没有将模拟密钥结果当作 Android Keystore 或实际 OTA 测试。
