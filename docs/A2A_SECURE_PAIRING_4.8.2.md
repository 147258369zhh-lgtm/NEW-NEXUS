# A2A 安全配对与连接控制（4.8.2）

本轮补强面向局域网和已有 HTTPS 入口的 A2A 首次配置，不把“能够复制地址”当成跨公网穿透能力。

## 使用流程

1. 在提供服务的设备打开“设置 → A2A Agents”，开启“允许其他设备调用这台手机”。
2. 确认页面显示 Agent Card 和 JSON-RPC 地址。点击“一键配对连接”旁的“复制”。
3. 在另一台 Eta 的 A2A 页面点击右上角粘贴图标，或在“添加 A2A Agent”中点击“从剪贴板导入配对信息”。
4. 核对显示名称、Agent Card 地址和 Token 已填入，再点击“发现并添加”。
5. 添加后可通过行尾开关暂停或恢复 Agent。暂停会在 Repository 层拒绝主动调用；删除会同时删除本机保存的认证信息。
6. 如连接信息泄露，在服务端点击 Token“轮换”；旧配对信息随即失效，需要重新配对。

## 安全边界

- 配对信息带显式版本字段和 URL 结构校验，支持 HTTPS 与用户明确填写的私网 HTTP。
- Token 和配对链接写入剪贴板时标记为敏感内容；导入不会自动联网或自动授权，仍需用户确认。
- 当前入站认证是设备级共享 Bearer Token，没有逐设备 Token、过期时间或独立撤销记录。轮换会撤销全部旧客户端。
- 配对信息不提供 NAT 穿透，不内置 tsnet/Headscale。跨公网时必须已有可访问的 HTTPS 隧道或反向代理。

## 验证

- `A2APairingCodeTest` 覆盖 HTTPS/局域网往返、名称与 Token 规范化、非法 scheme、嵌入凭据、损坏载荷、未知版本和字段上限。
- A2A Repository 的启停查询与 UI 已接线；真实局域网双向连接、Keystore 和 ColorOS 16/17 后台监听仍需真机验收。
