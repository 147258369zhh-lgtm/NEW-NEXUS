# P02 共同消息时间线与会议身份（2026-11-07）

这是原 P02.1 的继续开发，不是新增批次，P02 仍未完成。用户要求每两个原计划完整批次完成并验证后导出桌面 APK；目前 P01 完成，P02 继续推进，没有提前打包。

## 已接线的能力

- 两个会议入口通过同一个 MeetingRoomContent 物理复用普通聊天的 AgentConversationMessages、ChatMessageItem、Markdown、附件引用解析和工作过程展示通道。删除会议单独的 LazyColumn、纯文本气泡和另附末尾的主持汇总卡；消息保留原有顺序和 ID，汇总只呈现一次。
- 会议消息有成员名字、主持/系统/汇总标签及时间。身份来自该条历史消息，不拿当前轮的活动任务装饰旧消息；会议归属会屏蔽外层角色扮演身份。普通聊天和角色回复的默认身份/操作保持，现有悬浮层调用无需传新配置。
- 会议每位已完成参与者和主持人的正文都可复制，复用已有朗读入口（取决于上层是否启用播放控制器）；另一成员仍运行时不会把所有已完成结果的复制入口藏掉。会议用户长按保留复制，隐藏尚不支持的编辑/删除/分支；助手不显示无效的编辑、重新生成、删除、分支及候选切换。
- 主持汇总沿用预览行数设置，0 行可以先只看标题并主动展开；展开使用真正 Markdown，复制始终取完整原文。汇总不再为了突出显示而移动到后来系统消息之后。
- 无障碍等待根据最新类型化事件呈现共同状态卡和真实停止入口，不猜正文文字。旧轮次、停止后的房间不产生活动等待控制；损坏/旧版元数据退回原可读说明，普通系统说明不再全部染成错误红色。事件查询只取每张等待卡最新阶段，完整日志仍保留；不新增数据库版本。
- 共用时间线增加可选工作归属边界，避免相邻的不同成员/运行合并成一组，并保留普通聊天的工作组身份复用和分页锚点行为。这是显示通道准备：**会议 Runtime 的工具/流式事件录入仍未接完，本次没有声称已能显示真实会议工具进度**。
- 会议首次打开仍定位最新消息；关闭自动跟随后，收到新消息不会拉走正在阅读的位置。明确发送定位本轮已接收的用户消息，未采用旧的“尾部还差几条就强拉”的独立跟底逻辑。
- 共同用户图片列表改用 FlowRow，多张图片会换行，避免窄屏横向溢出；没有改变附件导入、授权或未发送附件的持久化协议。
