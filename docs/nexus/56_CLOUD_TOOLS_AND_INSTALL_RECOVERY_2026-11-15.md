调研来源为 [54 号官方 API 核对](54_CLOUD_API_CAPABILITIES_2026-11-15.md)；数字助理入口的上一批修复见 [55](55_ASSISTANT_ENTRY_RECOVERY_2026-11-15.md)，框架准备见 [57](57_SYSTEM_FRAMEWORK_PREPARATION_2026-11-15.md)。54 是调研时点记录，不能将其中“尚未实施”误当作本批的最终状态。

## 配置、权限和恢复

- 两个模型工具为 `cloud_document` / `cloud_media`，共24种操作；无需Root。主会话与会议成员通过现有工具目录、`cloud-tools`子智能体权限类别及运行审批链调用。
- 工具声明按外部副作用处理，恢复策略为 `REQUIRE_USER`，不把收费请求伪装成只读。完全访问仍遵守用户既定免应用审批规则，Android、账号和服务商权限不能由此绕过。
- 发现、激活及执行前使用同一可用性规则：总开关、具体能力开关、供应商路由、专用凭据、HTTPS端点均需有效。关闭后不能经全量懒加载目录重新激活；实际执行使用同一份已校验配置，避免检查与调用漂移。
- 原文件必须来自当前会话/会议已导入附件、明确绑定项目或本次运行成果，不能任意读取App私库后上传。成果写入受控工作区并登记 `artifact_id`、主题与项目归属，复用现有预览、导出和项目文件入口。
- Key通过现有加密存储保存；云凭据任一字段非空（包括只填一半百度/腾讯）都要求加密备份。旧备份缺字段按默认值兼容；解密失败不能以空草稿覆盖旧密钥。
- 收费操作要求稳定 `request_id`；提交前持久预约，进程中断或网络结果不确定时不自动重放。媒体任务保留账号、端点和主题/项目范围，恢复只查询原任务，并分批保存已经下载的成果。
- HTTPS上传禁自动重试与重定向；媒体成果只匿名下载官方结果域名，不携API Key。取消关闭正在进行的网络连接；客户端取消不保证供应商取消计费。
- 配置了备用服务商不表示任何错误都可自动切换：当前多供应商OCR只在明确的执行前拒绝等安全条件下回退；超时、5xx或未知结果不再次付费提交。

## Linux 能力包修复

此前Alpine v3.24 aarch64官方community索引可找到Noto中文字体和TeX相关包，不能把用户历史失败直接定性为“源缺包”。旧调用链会丢失长安装日志的末尾；强制升级存在后续命令缺少反馈的问题，字体就绪探测过宽，TeX中文依赖不全。未取得该次失败日志，不冒称已确认用户手机的唯一根因。

本批变更：

1. 升级/修复与原镜像选择进入同一次可观察事务，正常依赖不被无条件重装；实际命令退出码决定结果。
2. 能力卡保留等待、检查、下载、校验、安装、验证、完成与失败状态；提供可用的原生百分比/实际下载量，不按时间编造进度。APK事务百分比不能当网络字节，APT下载状态与安装状态分别显示。
3. 输出保留最后64KiB，正确切分回车进度，失败展示相关尾部日志和退出码；展示前移除控制字符及可识别的源凭据。
4. 中文字体探测要求实际匹配Noto CJK；Alpine TeX补 `texmf-dist-langchinese`。安装成功前验证XeLaTeX能够生成使用中文字体的PDF，已验证标记通过原子替换写入。
5. 字体/TeX安装和验证延长合理时限；“升级”表示向当前配置源请求升级或重装并重新验证，不保证当前源必然含更高版本。旁边的数字为实际探测版本，不是下载百分比。

## 验证与限制

本批相关检查共56个不同用例通过，涵盖云端协议/任务恢复/目录权限/凭据备份、语音协议和Linux安装诊断。初次源码编译通过，测试编译遇到本机Robolectric的 `getApplication()` 不接受泛型参数，修正两处测试调用后集中执行55项。52项通过，3项恢复检查揭示Windows测试环境的 `AtomicFile` 底层 `File.renameTo` 无法覆盖既有文件；已核对SDK字节码和仓内既有同类shadow，保持生产Android原子写实现不变，仅在这两个恢复测试替换rename为原子覆盖。随后只复验3个失败用例及新增的原子提交/回滚用例，4项通过，用时9秒；没有重复跑其余52项。

所有HTTP执行检查由本地fixture作答，不发真实收费API，不以编译成功代替账号、字体/TeX真安装或系统手势验收。检查日志和两轮XML分别保留桌面交付目录 `checks/initial`、`checks/recovery`。最终APK摘要及覆盖安装状态见下节。
