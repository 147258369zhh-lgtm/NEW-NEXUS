# 总模型请求额度与费用回执

## 真实接线

`AgentRuntimeService → NexusRunApplicationApi → RunModelBudgetCoordinator` 给根 Controller、子 Controller 绑定同一事务预算。`AgentModelClient` 和 `AgentContextSummarizer` 包装真实 Provider，模型入口先预占请求额度，再进入传输；每次兼容性重试和订阅认证刷新都会重新预占。压缩、备用模型和子 Agent 不另建无关额度。

执行库 v5 新增 `execution_model_requests`，同事务写入预算开始/结算事件、Item、请求计数和费用回执。每条记录绑定 RunId/FamilyRunId、目的、模型、冻结价格版本和归一化用量，不保存凭据、提示词或回复正文。v1/v2/v3/v4 显式迁移保留已有事件、Checkpoint、原始与有效预算，备份实际验证新记录的导出与还原。

父任务的 `hardRounds` 现在也是整组运行的模型请求总上限，子任务还有自己的上限。并发预占在 SQLite 事务内裁决；超额请求不会进入 Provider。失败、取消和无回执请求保留计数，不能靠重试清零。取消后迟到的回执可以结算，但不能重新打开 Run；开放请求未结算时不能提交成功终态。

## 费用行为与边界

- Goal 工具支持 `cost_limit_micros` 和 `cost_currency`，例如 `1000000`、`CNY` 表示人民币 1 元；模型价格继续使用运行统计中的现有配置入口。
- 同一组任务使用冻结价格版本，按现有协议归一化输入、输出、缓存读取和写入用量计算费用；不足百万分之一货币单位的结果向上取整。
- 没有价格、币种不同、用量不完整或此前费用无法确认时，有费用限额的任务停止后续请求，不能当作零费用。未设费用限额时仍记录未知状态，不阻断普通使用。
- 明确内置的 LiteRT-LM、llama.cpp、MNN 本机推理按零 API 费用记录；外部“本地服务”不会自动假定免费。
- 有费用限额时，同一组的并发请求等上一笔结算后再准入，避免多个请求同时透支同一份已知余额；取消可释放等待。
- 诊断入口 `state.runtime.executionEvidence` 显示整组请求数、开放请求、未知费用、已知费用、币种及费用限额。

当前是**已回执费用的停止阈值**：达到阈值后不再发送下一请求，但单笔已经发送的请求可能使最终费用超过阈值。跨协议输出 token 限制与单笔费用预留尚未完成，因此 N1 的严格费用上限仍为 PARTIAL，不能宣称硬封顶。第三方平台的额外计费也不由 token 回执证明。
