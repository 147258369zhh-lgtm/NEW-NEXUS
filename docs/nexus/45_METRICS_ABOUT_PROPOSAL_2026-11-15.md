# 运行统计与关于页面整改方案（待用户确认）

日期：2026-11-15。依据当前源码只读盘点；本文件与独立HTML是方案，不代表功能已实施。不改产品UI、不编译、不操作模型。本项不包含在2026111508包中。

## 1. 当前情况与优先级

设置中的总运行统计已经有概览、历史、管理，以及周期、来源、服务商、模型、项目、结果筛选；包含活跃日历、趋势、用量分布、计价、导出和清除，不需要另起一套统计。

会话/会议室详情已经有运行概览、7天Token趋势、模型分布，但只在进入时读取一次；“运行记录·N”目前没有实际明细列表。应首先修复实时性和可追溯性。

当前仅保留最近200条已结束运行，另保留运行中记录；淘汰会级联删除相关模型、请求、子作用域与事件。页面“全部”不等于终身累计。事件最多512条，每作用域请求最多512条，单次落库最多4096请求；超长运行应提示明细截断。

## 2. 能显示什么

| 内容 | 现有依据 | 建议展示 | 必须说明的边界 |
| --- | --- | --- | --- |
| 运行数量、结果 | Runtime运行记录 | 数字＋运行/成功/失败/取消/中断状态条；点击筛选历史 | 执行成功不表示用户目标一定实现；启动前配置失败未必入库 |
| 输入、输出Token | 服务商用量回执 | 主数字＋输入/输出趋势堆叠柱；点击看精确值 | 空值显示“未报告”，部分上报显示覆盖率；不能绘成0 |
| 缓存、思考Token | 服务商可选回执与计费归一化字段 | 次级明细、命中比例，注明分母和样本 | 缓存/思考可能分别包含于输入/输出，不作为总量额外叠加 |
| 估算费用 | 调用时冻结单价与用量 | 费用卡、按币种折线及模型费用排行 | 非实际账单；不自动换汇；没有价格/用量显示“未计价/部分估算” |
| 模型请求及重试 | 每次真实请求尝试记录 | 请求数/重试数；请求列表和结果条 | 逻辑轮数、重试次数、实际请求数分开，不把重试当新用户任务 |
| 响应耗时、首段文字、请求总耗时 | HTTP响应、首段文字及结束事件 | 小型数值卡；样本充分时P50/P95、分布图 | 首段文字不是首个推理Token；显示有效样本数 |
| 生成速度 | 请求输出Token和请求计时 | 请求级Token/s及分布 | 根运行总时长含工具/审批/等待，仅可叫“运行吞吐”；并行子任务不能相加当墙钟耗时 |
| 工具执行 | 成功、失败、未结算计数与有限事件 | 成功/失败/未结算横向状态条；进运行详情查有限事件 | 没有完整工具明细表，暂不做可靠的历史工具耗时排行榜 |
| 审批 | 整次运行请求/通过/拒绝/超时/取消/失败 | 紧凑状态条、点击查看整次运行 | 不能把整次审批计数重复加到多个模型/子Agent |
| 子Agent、压缩 | 独立作用域、父子关联、模型/用量/时长/状态 | 可展开作用域树、模型消耗条形图 | 主模型＋子作用域为总量，不能再叠加根运行指标 |
| 会话、项目、来源分布 | 持久归属字段 | 横向排行；点击下钻历史 | 项目为运行开始时快照；来源需把“外部”拆清楚 |
| 本地模型性能 | 独立本地采集库 | 独立折叠区：加载/首Token/预填充/解码、后端与缓存 | 后端有差异；没有功耗、温度或内存实测。主记录被清后可能失去会话归属 |

不承诺当前能展示准确的CPU/电池消耗、每个MCP历史耗时、真正支付账单或远程Agent内部用量。缺失指标先补采集再展示。

## 3. 先统一计算规则

1. 总览、趋势、来源分布、模型排行、导出共用一份归一化聚合；模型筛选作用于同一批模型作用域用量。运行数量/结果仍按关联根运行计算，并明确口径。
2. 已有主模型与子作用域明细时，只累加这些明细；旧记录缺明细才回退根指标，并标记粒度。
3. 修复来源分布漏子Agent/压缩及模型筛选不一致；修复多个模型重复审批计数。
4. 协议归一化优先：核对请求合并是否覆盖Anthropic独立缓存、Gemini思考计费输出；请求、运行、费用应相互一致。不能统一用“输入减缓存”覆盖所有协议。
5. 缺失值保留null；0仅表示真实报告为0。部分上报仅显示已知部分，同时显示覆盖率。
6. 图表按选定区间起止日绘制，修复历史自定义区间仍锚定今天；当前按运行开始日入桶，跨午夜归开始日，必须说明。
7. 成功率各自计算：运行成功率、模型请求成功率、工具成功率不能混用。取消/中断不混成故障；无有效样本显示“—”。
8. 费用按币种分别相加，沿用历史价格快照；取消或失败请求已报告用量仍计入消耗。修改当前价格不应悄悄重算已冻结历史。

保留现有“概览 / 历史 / 管理”结构，不增加第四套导航。


历史页使用紧凑运行记录：时间、所属会话/会议室、模型、状态、Token、估算费用、耗时；点击进入现有运行详情。管理页保留计价、导出、清除，并明确清除范围。

首屏仅四个重点数字，其余下沉；不堆十多个大色块，不做三维统计图。长模型名保留可展开/完整访问入口，大数字使用等宽数字，读屏提供图表数值列表。颜色沿用当前两套皮肤的语义色，并用文字/图形双重区分。

## 5. 单会话和会议室

保留右侧详情的“运行统计 / 项目文件”。统计内可切“本次运行 / 整个会话”，后者明确为可保留历史范围。

```text
当前会话 / 会议室
[本次运行] [整个会话]
状态、当前模型、开始时间、保留范围
Token / 估算费用 / 请求 / 耗时（2×2）
消耗趋势（多次运行）或请求时序（单次运行）
主模型 / 子Agent / 压缩用量（可展开）
具体运行记录 → 现有请求、错误、事件明细
```

仅可见时订阅当前主体的Flow；后台增量聚合、有界查询，进详情不扫描全部聊天消息。统计、项目文件分别懒加载。运行事件合并更新，数字不每次交叉淡入，离页停止UI订阅，不逐帧重绘图表或常驻玻璃捕获。

会议室增加成员任务结果横向条、实际模型排行；模板会议可加有真实检查点依据的阶段时间轴。先补`roomId/participantId/meetingTaskId/turnId/stageId/runId`的显式关联，再显示成员费用、速度和阶段分摊；旧记录不能靠字符串猜测补全。

本机主持规划、成员工作、阶段、汇总各是独立run，运行数不等于会议轮数。远程A2A目前绕过本机Runtime，只能显示远程任务状态；未获远端回执时Token、费用、速度显示“远端未报告”。普通会议没有单场生命周期，房间创建至今不能当执行耗时。

## 6. 长期统计建议

建议增加按天、模型、来源等维度的持久聚合，详细记录继续有界保留。这样长期总量不随200条明细淘汰而下降，进入页面也不用读取全部历史。汇总应采用runId/revision增量差额幂等更新，避免重复入账；恢复、备份导入与清除须使用一致账本。

旧版本已经淘汰的数据无法恢复，应从升级时真实可得记录建立基线，显示覆盖起点；不能伪称“安装以来”。汇总首版明确支持哪些筛选组合，不能将无法交叉重建的筛选数据拼成“精确终身总计”。区分“清除明细”和“重置统计”，避免隐性重置累计。

## 8. 微信＋支付宝双面实体赞赏牌

推荐一块可翻转的圆角实体牌：正面微信，背面支付宝。牌体为干净白色，边缘有薄厚度、细高光，阴影随旋转变化；经典皮肤是白色瓷感，玻璃皮肤仅牌框与环境采用现有玻璃材质，二维码区域始终不透明、高对比。

- 点击“微信/支付宝”直接翻面，水平拖动可以转满360°；松手按角度和速度吸附到正面/背面，约450ms收尾，轻微回弹，无自动持续自转。
- 两面文字/二维码分别绘制，背面不显示镜像；不在旋转中执行长按保存。扫码内容保持原图，不重绘、不换色、不加水印，不把光斑扫到码上。
- 长按当前面二维码约500ms保存到系统相册，同时提供显式“保存当前码”，避免用户不知道长按。保存**原始图片**，不保存带透视/阴影的展示截图。
- Android使用MediaStore后台写入，保存完成提示，可处理空间不足/写入失败；拖动超过阈值取消长按，避免翻牌误触保存。无障碍支持切面/保存，减少动画时快速淡入切面。
- 图片静态缓存，翻转用原生图层变换，无需集成WebView/三维引擎；仅交互期间更新，离页停止。
