# 会议室真实分工修复与 Run 上下文关联

## 会议室故障与修改

本批按用户实际反馈优先修复会议室，不重复全项目审计。代码中确认了三条会让主持人接管成员工作的路径：

1. `askHostToPlan` 使用与工作成员相同的完成函数，默认阶段可调用执行工具；主持人的通用角色指令也被放入分工请求。
2. JSON 分工解析失败时，`resolveTargets` 静默返回主持人和原始任务，随后按普通工作成员启动主持人。
3. `@主持人` 被当成直接执行成员，绕过分工；`@主持人 @成员` 还会让主持人和成员重复做同一工作。

现在真实链路是：

```text
无 @ 或 @ 主持人 → 仅分工的主持人请求 → 有效成员任务写入 meeting_tasks
 → 各成员独立 Runtime 请求与工具权限 → 真实任务结果/失败状态 → 仅汇总的主持人请求
```

- 增加 PLANNING / WORK / SUMMARY 阶段。本机主持人在分工和汇总阶段既没有工具 schema，也没有可执行的工具白名单；关闭 Hosted Search 和自定义请求体工具注入。
- 工作成员保留原权限与外部调用边界的交集，不因主持人受到限制而失去工具。
- 使用专门的分工/汇总系统指令，不再混用“亲自完成任务”的工作成员指令。
- 不可用分工最多修正一次。仍失败就明确显示未启动，保留已有结果；不假装分派，不改成主持人做全部任务。
- JSON 解析支持代码块、前置说明、多个独立 JSON、字符串中的花括号。名单大小写统一处理，过滤禁用成员、主持人自派发和无效临时成员。
- `@主持人` 进入分工；同时 @ 主持人和指定成员时，由指定成员执行，主持人汇总。自动分派无 @ 消息的开关不会阻止明确 @ 主持人。
- 临时专家仍通过原 Repository 持久创建，然后成为真实任务执行者；保留并发上限、失败状态、独立上下文和工具事件。
- 修复工作成员调用遗漏附件的问题：文件引用及图片继续进入成员实际请求。
- 本机主持人的 canonical 来源改为 MEETING_HOST，成员仍为 MEETING_PARTICIPANT。

`MeetingParticipantRuntime` 是配置和统一执行端口。默认实现继续调用 RuntimeConfigRepository 与 AgentExecutionPort；不增加第二个 Agent Loop。测试可替换该端口以驱动真实编排和 Room 写入。

远程 A2A 主持人继续保留原能力并收到阶段职责说明；远端是否执行工具还取决于对端实现。本批不宣称已经对任意第三方 A2A Server 强制实现无工具沙盒，完整远端权限仍在 N6。

## 同步补齐的 N1 接线

- `NexusRunContextResolver` 在成功准入分支中读取真实会话/会议/自动任务项目关联，以及当前 Goal/Plan 的有效 GoalId 和预算；拒绝或重复请求不重复初始化上下文。
- 待初始化的分支从已保存的继承配置/项目回执读取预期项目。实际分支初始化仍在执行工作线程进行，不移到主线程做跨库写入。
- Canonical Run、Session 和执行器共享准入时保存的项目/目标/预算。会话运行中移动项目不会改写该 Run 的历史关联。
- Metrics 接收明确的准入项目；空字符串明确表示当时没有项目，不再被稍后变更的绑定替换。旧调用未提供项目时保留原兼容读取。
- `RunBudget.intersect` 统一按更严的一侧合并，软阈值不超过硬阈值；子 Run 同样继承项目、GoalId 和预算交集。
- 执行侧读取 Goal 文件时，损坏或不兼容状态必须失败，不把它默认为空目标并扩大预算。

这里补齐的是关联和已有硬预算接线。Goal 的软预算等待、追加预算、费用总额及所有来源仍需继续，不把这些字段存在视为全部实现。
