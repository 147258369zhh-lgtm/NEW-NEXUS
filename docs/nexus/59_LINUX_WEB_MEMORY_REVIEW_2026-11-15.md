## 本批范围

用户要求检查普通模式 Python/Node 能力包安装失败，将“网页搜索与读取”放入云端工具，并重新研究记忆与自学习的实际使用、缺陷及分层增强。随后明确允许暂停手机操作，现场复现安装；不发送聊天或调用付费模型。

本批只修改上述网页设置入口及确认的后台缺陷；没有重新设计记忆页面、改变其他界面、重建数据库或扩大工具权限。下文的增强方案与已经实现的功能分开记录。

## 一、普通模式安装失败的实际原因

设备 OPPO PHY110（1fe75f23），应用1519。现场页面是 Debian 13.1、普通模式 PRoot、普通应用身份；基础工具和环境就绪标记均存在。依次点击 Python 脚本和 Node.js 运行的安装，两项均得到：

```text
Syntax error in regexp pattern near index 11
\{([^{}]+)}
```

故障发生于 `LinuxSourceSettings.validateUrl` 解析下载来源模板。旧正则转义了左花括号但未转义右花括号，Windows JVM接受，安卓ICU正则拒绝；因此尚未进入归档下载就终止，不能把此故障归因为Root、版本不匹配或镜像缺包。Node先完成包管理器前置步骤后，同样在模板校验阶段失败。现场 `opt/eta` 尚不存在，与此阶段相符。

修复为直接扫描四种白名单占位符 `{version}`、`{file}`、`{arch}`、`{official}`，不再依赖该正则。保留HTTPS、无凭据、端口及路径校验，拒绝未闭合、空白、未知和嵌套占位符；保留国内/官方源、用户自定义源、固定归档摘要和版本。本批没有绕开校验或改用Root安装。

调研时官方UV GNU ARM64与Node ARM64归档的大小、SHA-256及结构与源码固定清单一致。手机最新版检查中的UV GitHub API 403是另一条可选检查链；固定版本安装并不依赖该API，不能把它当成本次模板错误根因。

## 二、网页工具归类

1520首先移除“系统与工具”服务列表中单独的“网页搜索与读取”行，使用已有云端页面底部入口。用户在手机查看后指出找不到上方搜索能力，因此这一步只移动入口未达到预期，不能作为最终完成。

按追加反馈，最终改为云端工具能力分类中的首项“网页搜索与读取”，默认直接展示“网页搜索”，具体能力可切换“网页读取”。在本页选择内置默认、DeepSeek或自定义接口，并直接配置对应凭据、地址与字段映射，不再要求翻到页面底部找另一个入口。保留设置搜索直达与旧网页配置路由兼容；Cloud/Web分别保存自己的草稿，分类切换保留草稿，离开检查两份未保存状态，保存按钮只写当前可见的配置所有者，不伪装为跨存储原子事务。

搜索、读取的服务商、配置、凭据、开关、深链接及实际工具调用沿用原有所有者。归类不意味着网页功能新增受云端OCR总开关控制，不迁移或重复保存密钥，不影响语音的原有归类。

## 三、已经生效的经验到底如何使用

这里的“自学习”是可审阅经验库和运行时参考，不是对模型权重做训练。

```text
用户经验/失败证据 → 候选 → 审查 → 用户确认/晋升 → active规则
                                                   ↓
普通任务开始 → 读取active规则 → 置顶优先、其余最近更新优先
                           ↓
                     默认最多2400字符
                           ↓
             作为背景资料注入本次模型请求
                           ↓
         模型参考经验，并依当前任务和真实工具结果执行
```

- `active`表示规则有资格被读取，不能等同于每一条都已进入本轮请求，更不能等同于模型确实采用。当前默认是按排序拼接后截取2400字符，并非先针对本次任务相关性挑选；后面的经验可能没有注入。
- 模型可以主动调用 `learning_search` 查找其余生效经验。当前是标题/正文关键词匹配，不能声称是真正的向量语义检索，也没有程序保证每次任务一定先搜经验。
- 规则通常在下一次运行开始时重新读取；本次运行中途启用新规则不会自动改写已经冻结的请求背景。
- 经验是背景，当前用户要求和真实观察优先；不能借经验改变审批或系统权限。
- 自动记忆整理主要从用户原话及补充提取候选，排除角色剧情；不能宣传为每次工具成功后自动学会整套可靠流程。Skill/工作流等已有可执行能力是不同链路。

主要所有者：`fork/learning/LearningRepository.kt`、`LearningDao.kt`、`AgentLearningTools.kt`；实际调用在 `agent/runtime/AgentRuntimeRunExecutor.kt`，注入在 `agent/model/AgentPromptBuilder.kt`。

## 四、现有记忆能力，不能重复建设

| 现有结构 | 实际能力 | 当前边界 |
| --- | --- | --- |
| 文档内容层 | 核心、项目、任务、长期、工作、其他 | 是同一Markdown文档内的内容章节，不等同于读取范围 |
| 文件作用域 | 全局、项目、会话、定时任务、会议 | 每次运行挂载当前全局及关联的局部范围，不主动读取其他项目 |
| 已确认结构化记忆 | 层、作用域、来源、证据、状态、过期、替代关系 | 有效状态及未过期过滤已有，不需另建一套审核库 |
| 记忆检索 | 关键词、来源、时间、作用域排序及命中说明 | 语义评分接口已有，但生产未绑定向量评分实现，当前走本地信号 |
| 角色记忆 | 按characterId独立保存，可跨同角色会话复用 | 剧情与现实记忆应继续隔离 |
| 自学习规则 | 审核、确认、启用、版本、归档、置顶、回滚 | 规则表本身尚无projectId/scope/characterId，目前仍是全局经验库 |

全局核心按上下文预算注入，局部文档及审核条目沿已有链路加入，不是把所有完整记忆无条件塞给模型。普通记忆的跨项目隔离已存在，但不能据此宣称全局自学习规则已经拥有相同的项目隔离。

## 五、本批确认并修复的后台问题

| 缺陷 | 影响 | 本批修复 |
| --- | --- | --- |
| `memory_write`中layer覆盖显式scope | 指定项目范围，却可能因工作层写入当前会话；clear/replace也可能被重定向 | 显式scope优先；layer仅用于append章节，缺省scope的append保留旧推导；原范围及权限门禁不变 |
| 分层追加丢失已知章节之前的旧文档前言 | parse/render后整份替换会遗漏前言或未分类标题 | 保留preamble，现实和角色两个追加入口均保留原内容，不强迁移旧文件 |
| 单字经验检索误匹配全量规则 | 例如查“根”返回不含该字的经验 | 短查询必须命中实际子串，不能通过空词条件匹配所有记录 |
| 内置本地模型把学习依附于记忆总开关 | “记忆关闭、自学习开启”时云模型仍收到经验，本地模型却丢失 | 本地提示也独立使用已启用的学习经验，沿用预算；未改变角色隔离 |

未将以下问题冒称已完成：2400字符按完整规则分配、任务相关检索自动注入、项目经验数据库迁移、向量服务生产接线、采用证据界面。角色中的learning工具暴露规则也需要明确；现有候选仍需确认，不能把它直接描述为已经自动污染全局库。

## 六、建议的分层方案（尚未实施）

“核心”与“全局/项目”应分成两个维度：**核心决定重要性和注入预算，作用域决定在哪里可见。** 一条项目记忆也可以是这个项目的核心，不应因标记核心就泄露给其他项目。

| 用户能理解的类别 | 应保存什么 | 使用范围及策略 |
| --- | --- | --- |
| 核心记忆 | 用户明确确认的稳定身份、长期偏好、稳定约束；项目关键规则也可标核心 | 在所属作用域内优先、小预算常驻；自动提取先给候选，不能静默覆盖关键事实 |
| 全局记忆 | 跨项目通用的交流偏好、常用环境和通用事实 | 普通任务可读取；不放某项目专属路径、凭据或剧情 |
| 项目记忆 | 当前项目路径、技术栈、决定、项目专属流程及问题修复 | 仅绑定此项目的会话/任务/会议读取；不能在切项目后继续混用 |
| 会话/任务记忆 | 当前目标、进度、待办、临时条件 | 当前范围内使用，支持过期、完成后归档或经确认晋升 |
| 会议记忆 | 本会议决定、角色分工、共同事实 | 仅当前会议及明确绑定项目；是否给成员共享需与会议可见性一致 |
| 角色记忆 | 人物设定、剧情事实、世界状态 | 仅该角色；不自动写入现实全局经验 |
| 经验规则 | 可复用操作流程、失败原因和修复方法 | 每条也有作用域及来源；默认局部，确认跨项目通用后才提升全局 |

不建议建立七套互不相通的存储系统。应复用已有作用域、章节、审核和版本结构，补上学习规则自身的范围，并让界面把范围与内容类型清楚区分。

### 建议的实现顺序

1. **先可靠使用**：核心稳定注入、当前局部状态、按任务检索的相关经验。先按作用域过滤再排序，预算按完整条目分配，不从某条规则中间截断；避免置顶经验永久挤掉所有其他经验。
2. **再完善经验作用域**：给现有经验补global/project/conversation/task/meeting/character归属；旧数据兼容为global，保留ID、版本和用户确认记录，不能删除重建。
3. **补冲突与寿命**：当前用户明确要求优先，其次当前任务与项目约束，再到全局偏好；更新事实保留来源和替代关系，临时记忆到期，不让旧版本并列互相矛盾。
4. **补可解释性**：后台记录本轮实际注入、检索命中、预算排除和后续结果，区分“规则已启用”“本轮已提供”“结果证据支持采用”，不编造采用率。
5. **最后改管理界面**：在现有“记忆与自学习”中提供范围和内容类型选择，以及本轮使用说明；具体页面、控件及布局需另经用户同意。本批不实施该界面方案。

第一阶段无需立即引入云向量服务。先用已有关键词、范围、来源和时间检索做可验证改善，再决定是否接入embedding及本地索引，避免先增加费用、网络依赖和首轮延迟。
