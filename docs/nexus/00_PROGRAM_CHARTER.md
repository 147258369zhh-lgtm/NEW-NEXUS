# Nexus 大改程序章程

## 1. 产品定义

Nexus 是承接 Eta 现有能力的新 Android Agent 产品。它继承 Eta 已有 Runtime、会话、会议室、工具、MCP、A2A、Skills、本地模型、语音、Linux 和文件能力，但使用新的产品身份和长期架构。

旧 Eta 是迁移来源与历史基线，不是 Nexus 的常规上游。Nexus 发布后独立维护 Provider、依赖、Android 兼容、安全修复和插件生态。

## 2. 产品目标

Nexus 同时满足：

- 长期个人使用的稳定性与隐私。
- 可公开发布的安装、权限和迁移能力。
- 可多人开发的模块化源码结构。
- 可接入 MCP、Agent Skills、DSH/Cordis、A2A、Linux 和原生插件。
- 移动端优先执行，同时支持电脑、服务器和远端 DSH Host。

## 3. Nexus 安装身份

- 用户可见名称：Nexus。
- 推荐 applicationId：`io.github.zhh_lgtm.nexus`。
- 与旧 Eta 可并存安装，不能覆盖旧包。
- 使用独立数据目录、通知渠道、服务标识、文件 Provider authority、备份格式与签名身份。
- 旧 Kotlin namespace 允许在迁移期保留；用户可见名称和安装 ID 必须先切换。
- 旧 Eta 数据不能直接跨应用沙盒读取，需要导出迁移包后在 Nexus 首次启动导入。

## 4. 不可破坏约束

1. 普通聊天、会议室、目标、A2A、定时任务和插件必须共享同一执行语义。
2. 工具是否暴露给模型与是否允许执行必须使用同一权限白名单。
3. 高风险操作不能由模型自行批准。
4. 第三方插件不得运行在 UI 主进程。
5. 密钥不可读取明文，只能设置、替换和清除。
6. 审计和回滚不可关闭。
7. 不可逆操作不能因崩溃恢复而自动重放。
8. 大型模型、Linux 和插件 Host 不得挤占前台 Agent。
9. Classic 和 Omni 功能完整度必须一致。
10. 没有真实设备和端到端证据，不得宣称高风险功能完成。

## 5. 关键决策记录

| 主题 | 决策 |
|---|---|
| 产品路线 | 稳定、公开、开源三种质量目标同时成立，先稳定再扩张 |
| 执行模型 | Session、Run、Turn、Item 分离；Task/Goal 只用于持久工作 |
| 上下文 | 默认能力目录，按需检索；热门工具动态预加载 |
| 热门工具 | 6～12 个默认，动态上限 16 |
| 模型路由 | 用户指定优先级；按任务、成本、隐私、本地可用性自动选择 |
| 模型回退 | 允许跨供应商，但必须满足当前数据授权 |
| 云端数据 | 当前任务必需内容；记忆、附件、截图、语音、文件按范围授权 |
| 本地模型 | 已安装可自动加载；新模型下载需确认 |
| 插件隔离 | 内置工具同进程；第三方插件独立 Sandbox Host；常用 Host 预热 |
| 插件恢复 | 插件失败只隔离并撤销自身资源 |
| 插件审计 | 安装/升级/来源/权限/哈希变化重审；Agent 审计不能替代 Root 用户确认 |
| DSH | 远端和本机 Host 都按完整插槽验收 |
| Linux | 独立 Host，多发行版，按需下载 |
| A2A 信任 | 任一 Tailnet 节点自动发现；Tailnet 地址 + Agent Card + Bearer Token 全匹配 |
| A2A 会话 | 首次认证请求开始 24 小时安全会话 |
| A2A 高危 | 每次本机审批，超时拒绝当前工具 |
| A2A 文件 | 用户授予 Nexus 的内容文件；排除私有数据库、Keystore 和凭据 |
| 设置修改 | 普通会话 Agent 可修改；远端 Agent 只能申请 |
| 密钥 | 不可读，可写、替换、清除 |
| 审计 | 永远开启，记录旧值、新值、来源和撤销 |
| 计划模式 | 允许计划、记事本及提醒草稿；其他文件和设置只读 |
| 目标模式 | 会话级，可提升到项目；软预算暂停，用户确认完成 |
| 会议室 | 主持人监督器；长期 Agent；临时专家；默认 4 并发 |
| 同会话并发 | 一个主 Run + 最多一个后台 Goal Run |
| 记事本 | 会话附件；顶部下拉抽屉；Revision；Agent 可直接整理 |
| 夜间整理 | 本地提醒可自动；计划和重要操作需确认 |
| UI | Classic/Omni 共享业务和导航，布局与视觉 Profile 独立 |
| 字体 | 界面、正文、Markdown、代码、公式分别设置 |
| 文件 | Run 临时 > 会话 > 项目 > App 默认；项目跨 Host 显式挂载 |
| 备份 | 分类导出；模型/Host 独立可选包；凭据需密码与 Keystore 重包裹 |
| 诊断 | 默认本地；匿名上传需开启；正文需单独授权 |
| 后台 | 前台任务继续；进程死亡安全恢复；重启恢复 A2A/定时/Goal |
| 上游 | 常规同步停止；重大安全或兼容修复允许人工移植 |

## 6. 发布策略

- 每个独立阶段生成内部测试版。
- 阶段文档、自动测试、Release 构建和真机验收全部通过后才能标为稳定版。
- DSH 全部插槽未验收时，稳定版不得启用或宣称 DSH 插件兼容。
- 旧 Eta 与 Nexus 各自保留独立版本号；Nexus 可以从 1.0.0 开始。
- 未明确授权时不执行 Git、签名迁移、正式发布或覆盖安装。
