# NEXA 记忆、自学习、角色指令与智能体整合调研

日期：2026-11-16。基于当前1521源码的静态核查；本轮产出为研究和拟议方案，没有修改产品代码、构建安装包、操作手机或调用模型服务。下文将已实现能力、确认缺口和待验收风险分开。

后续实施索引：用户已批准的本批功能现已随2026111601交付，实际完成范围、检查、安装与尚未实施项见[61号实施记录](61_MEMORY_BEHAVIOR_AGENT_IMPLEMENTATION_2026-11-16.md)。本报告保留1521调研时点，不把所有长期建议视为已完成。

## 1. 核心结论

| 用户关心的问题 | 源码结论 | 建议 |
| --- | --- | --- |
| 记忆有没有分类 | 已有内容层、可见范围、审核记录和角色记忆，分类未充分转化为按需读取 | 保留现有存储，统一选择本轮真正需要的条目 |
| 全局记忆是不是塞太多 | 有字符上限，但多个预算独立累加，主要取固定前缀，没有按当前任务自动检索 | 少量核心常驻，其余先按范围过滤，再按任务检索，统一预算 |
| 自学习应该存到哪里 | 已有独立经验规则库，不是都写进全局Markdown | 扩充现有经验库的作用域、证据和检索，不另造重复数据库 |
| 角色与指令为什么割裂 | 两个入口打开同一模板页，角色卡和模板仍各有系统/后置指令及装配链 | 合为一个行为配置功能，先统一装配，再合编辑与应用 |
| 内置Agent够不够 | 真正内置只有探索、编码、规划3种；12种会议用途是流程，不是12个专家 | 1个专属主持模板，加12类专业Agent，复用现有调度和权限 |

问题主要不在于缺少更多存储，而在于缺少统一的“哪些信息适用于当前任务、哪些实际进入请求”的选择与解释。

## 2. 记忆：分类已有，需要把保存范围与重要性分清

当前内容章节包括核心、项目、任务、长期、工作和其他；保存范围包括全局、项目、会话、任务和会议，角色剧情另按角色ID保存。

**核心是重要性，全局/项目是可见范围。** 项目里的关键规则可以是该项目的核心，但不应因此进入其他项目。反过来，在全局文件中写一个“项目记忆”标题，也不会自动获得项目隔离。

拟议管理方式：

| 用户看到的分类 | 存放内容 | 何时提供给模型 |
| --- | --- | --- |
| 核心记忆 | 明确确认的稳定偏好、身份、关键约束 | 只在所属范围内，以受限的小集合常驻 |
| 全局记忆 | 跨项目适用的常用环境和事实 | 与当前任务相关时检索提供 |
| 项目记忆 | 项目决定、路径、规范、当前状态 | 绑定该项目后可见，按任务选取 |
| 会话/任务记忆 | 当前目标、进度、临时条件 | 当前范围内使用，完成或过期后整理 |
| 会议记忆 | 本会议的共同事实、决议和待办 | 还需服从会议阶段及成员可见性 |
| 角色记忆 | 人物剧情、人物关系、世界状态 | 仅相应角色，不混入现实经验 |
| 经验库 | 可复用步骤、失败原因、已验证修复方法 | 按范围、任务与适用条件检索 |

界面可以按上述分类组织，底层继续保留“可见范围＋内容类型/优先级”两个维度，不建立七套互不相通的系统。

### 当前为什么仍然占较多上下文

普通云模型中，全局文件提取核心、补充内容和标题索引；局部文件、审核记忆、学习经验又各有一份预算。默认128k窗口下理论上限约为：

`核心8000＋补充4000＋标题4000＋局部6000＋审核4000＋经验2400＝28400字符`

这是字符，不是token；不含包装，实际通常更少。内置小模型另有紧凑装配，不能把上述数值套给所有模型。关键不足是各池独立，且多数按固定顺序取前缀，不能确保和本轮问题相关。固定会话快照有助缓存，但仍会随请求提供，并不等于不占上下文。

已有`memory_search`能搜索合法范围内的文件和结构化条目，包含关键词、时间、来源、范围等排序；目前需要模型主动调用，启动时没有自动按任务筛选。学习检索则较简单，尚未复用同一选择机制。语义评分接口存在，但生产没有绑定向量实现。

### 建议的读取流程

`当前任务 → 合法范围/状态/过期过滤 → 少量核心 → 相关事实与经验检索 → 去重/冲突处理 → 按完整条目分配总预算 → 记录实际选入及省略原因`

- 无相关条目就少提供，不为了填满预算硬塞记忆。
- 核心、事实和经验共享一个随模型窗口调整的总预算，给当前对话和工具结果预留空间。
- 较大的内容先给简短索引，必要时再读原文；保留来源和版本，不从半条规则处截断。
- 子Agent继承合法可见范围与任务约束，再按自己的子任务检索。当前直接共享父方记忆快照，仍有进一步压缩空间。
- 旧全局内容先产生归类建议及预览，保留原文、来源和可撤回记录；不能凭一段文字猜出项目后静默搬走。

## 3. 自学习：完善现有独立经验库

当前已经有候选、证据、规则、版本、变更和反馈表。普通经验的实际路径为：

`用户提供或运行中提出经验 → 候选 → 质量审核 → 用户确认/晋升 → 生效规则 → 后续任务背景或learning_search检索`

这属于持久经验和运行时参考，不是模型权重训练。当前质量审核主要是确定性文本、评分和证据门槛，不能证明模型提出的方法已经实测正确。

还有两条不能遗漏的既有链路：

1. 普通记忆自动整理从用户原话及补充提取事实候选，要求证据匹配原文；与流程经验不完全相同。
2. 工具经验到Skill已有真实结果和多运行证据要求，适合把稳定流程提炼成可执行技能，不能再重复建设一套。

### 正确的归宿与增强

经验继续放在现有经验库，分别记录“流程经验、失败原因、修复方法”等，并补充：

- 所属全局/项目/会话/任务/会议/角色范围。
- 适用工具、系统环境、版本与前置条件。
- 真实运行/工具来源、观察到的结果、验证状态。
- 生效、过期、被替代、失败反馈和回滚关系。

稳定用户偏好归事实/偏好记忆，操作方法归经验库；同一来源可以建立关联，避免复制两份互相矛盾。反复验证的流程可以沿已有Skill提炼链升级。审批偏好继续由独立审批逻辑处理，不能凭普通经验扩大执行权限。

### 当前确认的不足

- 学习候选和规则没有scope/projectId/characterId，查询和规则唯一键也未带范围。现有经验实际仍主要是全局库。
- 生效经验按置顶/更新时间拼接后取2400字符，缺少按当前任务选择、完整条目预算和实际使用说明。
- 经验提议中的部分来源/证据由模型传入，应由运行时绑定真实证据，区分“提出的做法”和“已验证的修复”。
- 角色聊天已排除自动学习注入和成功捕获，但学习工具暴露、执行及失败候选捕获尚有遗漏，仍可搜索现实经验或提出剧情候选。候选须确认后才生效，不能据此声称现实生效库已被自动污染。

## 4. 角色与指令：合成一个行为配置功能

建议继续使用一个“角色与指令”入口。进入后直接管理**行为方案**，不再把角色库作为必经独立主页，也不要求同一设定去两个地方填写。

同一方案集中管理：

| 模块 | 内容 |
| --- | --- |
| 身份与表达 | 名称、身份、语言、语气、表达风格；剧情人物为可选方案类型 |
| 职责与规则 | 要做什么、工作步骤、限制、输出格式及附加指令 |
| 适用范围 | 全局、项目、会话、模型、会议、主持/参与者、子Agent、自动任务 |
| 背景资料 | 世界书、示例、开场白及对应记忆的引用；不是全部常驻 |
| 工具边界 | 可用/禁用的结构化工具限制，展示真实生效交集 |
| 生效预览 | 本轮来源、继承、追加/替换/停用、预算省略及最终使用内容 |

现有头像、收藏、完整PNG/JSON角色卡、世界书、剧情人设、角色记忆、旧会话快照和备份能力保留，收进对应方案的可选模块。工作Agent仍保留职责、工具及执行配置，不能与剧情人物混成一个无差别人格。

### 后台也要统一

建立统一装配计划，将提供商提示词、角色卡、模板、Agent职责、当前工作模式和背景资料转成带来源、范围、位置、继承规则和预算的片段，再投影到具体模型接口。

配置中的明确覆盖应有追加/替换/停用语义；自由文本冲突无法仅凭排序可靠裁决，不能把“结构检查通过”说成“没有语义冲突”。当前用户明确要求优先于可配置偏好；记忆和外部资料作为背景。真实工具权限继续在运行时计算交集并执行前复核，提示词文字不能授予权限。

### 静态核查确认的问题

| 问题 | 影响及建议 |
| --- | --- |
| 角色系统/后置指令与模板重复配置 | 统一引用和编辑，避免两份相似内容叠加 |
| 模板作用域缺项目 | 补项目绑定；不能用全局模板代替项目规范 |
| 模板后置在当前输入前，角色后置在输入后且消息角色不同 | 统一位置语义并按Provider验收，不能仅改名称 |
| 页面提示支持角色宏，模板Resolver却原文拼接 | 对支持的宏按范围明确展开；无对应对象时说明未展开 |
| 全局模板先拼接，最终取前缀 | 大模板能挤掉具体会话/参与者规则；按优先级分配完整片段预算 |
| selected模板列表不等于实际进入请求的列表 | 预览和运行记录按实际生效片段生成 |
| UI可给主持人单独绑定参与者模板，运行却清空主持的参与者标识 | 修复绑定对象与运行作用域的一致性 |
| “工具边界”真正编辑仍在另一套工具页面 | 统一编辑流程，继续复用原结构化权限所有者 |

另有一个**静态高可信、尚未运行验收的风险**：内置本地模型的紧凑人格装配丢掉世界书投影用的标记，可能导致世界书没有注入。应列入后续专项检查，不能把它当成本轮已实机确认或已修复的问题。

完整角色导入不能直接改走目前的“从角色卡抽取提示词”入口；后者只提取少量指令字段，不能替代完整角色卡导入。

## 5. 默认Agent：1位主持＋12类专业岗位

当前真正内置只有explore、coder、plan。12种会议用途已经有独立编排，涵盖讨论、研究、交叉审查、核验、实施、会诊、写作、辩论、德尔菲、决策、交付和访谈，应复用它们。

会议已经强制唯一主持，但尚无独立内置主持Profile；创建时默认目录首项，纯默认库会选到探索模板。建议明确提供1个主持模板，并保留现有三种Agent的稳定ID，扩为以下目录。

| 岗位 | 主要交付 | 工具/模型侧重点 |
| --- | --- | --- |
| 主持协调 | 目标澄清、分工、依赖、比较分歧和最终汇总 | 结构化输出、推理可靠；由会议编排器按阶段调度 |
| 文件探索（保留explore） | 文件定位、证据及路径 | 文件只读、快速检索 |
| 网络研究 | 带来源日期的资料与研究结论 | 搜索、网页读取、长材料处理 |
| 事实核验 | 主张的已证实/错误/未决状态与依据 | 独立取证，必要时不同模型 |
| 方案规划（保留plan） | 分步方案、接口、依赖与取舍 | 只读资料、较强推理 |
| 编码实施（保留coder） | 代码或脚本产物、变更及验证交接 | 限定文件、终端和所需MCP |
| 独立审查与验证 | 有触发条件的问题、验收结果与证据 | 默认独立阅读，需实际检查时用受限终端 |
| 数据分析 | 口径、计算、图表和可复算结果 | 指定数据、脚本及计算工具 |
| 写作 | 面向指定读者的完整稿件 | 材料整合、写作能力 |
| 编辑与翻译 | 修订稿、译文和差异说明 | 语言能力及文稿读写 |
| 文档制作 | 文档、表格、演示和PDF等产物 | 已就绪的文档环境/云工具，先检查依赖 |
| 个人资料助理 | 授权范围内的日程、消息或账单摘要 | 仅开放本次需要的个人资料类别 |
| 设备诊断 | 状态、日志、故障证据和处理建议 | 设备只读检查；屏幕操作交主Agent |

岗位名称在界面使用中文，内部保留稳定标识。专业差异要体现在触发条件、输入、产物、工具、模型、预算和验证要求，不能只改名字、头像与一段人设。

### 已有能力不重做

已经支持每Agent的模型/思考强度、候选路由、工具白名单/禁用、上下文和工具次数、AI生成角色草稿；已有并行排队、活动快照、子运行记录及检查点。会议已有分阶段屏障、公开/定向/匿名材料和依赖检查。

普通子Agent不会获得完整主对话历史，但会继承父方记忆、技能和执行环境。普通子Agent禁止再次派子Agent、直接询问终端用户及操作GUI，不能把新主持模板当作可无限递归派工的普通子Agent。会议主持应由现有编排器组织。

## 6. Agent真正增强的重点

1. **主持职责接入实际阶段。** 现在规划、汇总、协调、访谈使用固定阶段提示，只有工作阶段加入Profile正文。新增主持模板必须正确参与阶段装配，同时保留规划不能执行、汇总不能冒充成员补做等规则。
2. **结构化派工和交接。** 派工包含目标、必要材料、负责文件、依赖、验收、预算和停止条件；返回成果、证据、实际验证、阻塞和未完成。独立审查不能只复述作者结论。普通会话也要处理多Agent同文件并写。
3. **模型选择进一步匹配任务。** 目前普通子Agent已有显式指定→专属绑定→全局→主会话的优先级；候选主要选首个合格。会议另有工具/推理/结构化/视觉/上下文评分及模型多样性选择，但还没有真实专业成功率、速度和费用评分。后续尊重用户绑定，再依据可用能力与实际表现选模型并说明原因。
4. **减少无关材料与工具。** 当前探索和规划默认只读集合也含较广泛个人资料；专业模板应按需要收窄，继承合法范围后按子任务选记忆和技能。工具白名单并不自动等于独立文件沙箱。
5. **把检查点接成可靠续接。** 普通resume现在主要依赖进程内缓存；已有持久检查点但尚未接成跨重启恢复。应复用它们恢复身份、角色版本、预算、历史和产物，先核对有副作用操作的结果，避免重复执行。
6. **与记忆/指令使用同一套选择和装配规则。** 模板库扩展时同步主Agent的目录提示、会议选择、模型绑定和实际工具过滤，不只增加卡片。

## 7. 建议实施顺序与边界

| 阶段 | 内容 | 预期成果 |
| --- | --- | --- |
| A 先减无效注入 | 统一范围过滤、相关检索、总预算、整条选取和去重 | 全局记忆与经验不再无差别常驻 |
| B 补经验归属 | 给现有候选/规则补范围、真实证据、过期替代和角色边界 | 学得有来源、用得有范围、错了可撤回 |
| C 统一行为装配 | 角色/模板/提供商/Agent职责的兼容适配，补项目和主持绑定 | 同一规则只有清楚来源与生效方式 |
| D 合并用户配置流程 | 一个角色与指令功能，背景/工具边界/应用/预览集中管理 | 不再维护分裂的两套相似配置 |
| E 扩充Agent目录 | 1主持＋12岗位，同步阶段职责、路由和任务交接 | 默认能派出有实际区别的专业Agent |
| F 可靠恢复及反馈 | 检查点续接、真实结果反馈、选择原因和使用记录 | 减少重做与重复副作用，逐步改进调度 |

旧全局数据和经验的迁移需保留原内容、ID、版本和已确认记录；无法确定范围时先保持原全局归属并给出归类建议。所有新增/重排页面均应按用户认可的本任务方案实施，沿用既有双皮肤和布局规范，不扩改其他界面。本报告是拟议计划，不代表上述增强已经实施。
