# 4.7.2 成本、运行轨迹与备份完善

版本：4.7.2-debug，versionCode 2026110709。

## 备份问题与恢复流程

用户反馈：导入时导入入口没有进度，反而是导出入口转圈，备份从未成功恢复。本轮把导出、读取校验、正式恢复分别建模；任务由 ViewModel 管理，旋转后保留任务和阶段。两处入口只显示自己的进度，正在处理时可取消，错误不会显示成成功。

导出：先选格式、内容和可选密码，再选目标文件；先在本机准备完整输出，再用缓冲流写入 Android 文件接口，目标成功关闭后才报告完成。读取导入文件同样在 IO 线程完成，显示已读字节，随后校验；确认覆盖范围后才恢复。错误密码、损坏文件、关联数据错误、未来数据库版本会在替换前拒绝。

全量回归还复现超大单字段内存不足：`Json.encodeToStream` 在转义 17 MiB 消息/上下文字符串时扩展巨型缓冲区。本轮改用序列化器生成当前记录的 JSON 结构，并由 Android `JsonWriter` 经固定大小字符缓冲输出；字符串保留原引用，不建立整条转义副本，仍逐条处理数组，不提高测试堆上限来跳过问题。原有超大单字段和总计超过 64 MiB 备份回归保持。

完整恢复先保留恢复前的私有安全快照，再发布待恢复目录。界面明确显示“重启完成恢复”；主进程重启时在 Room、DataStore 和 WorkManager 打开之前应用数据。恢复结果留有状态记录，中断/失败沿用回退机制。WorkManager 内部数据库不迁移，任务计划按恢复后的业务配置重新建立。自动备份目录和启用状态在完整恢复后重置，需要重新授权。

安全快照位于应用私有 `eta_restore_control/pre-restore.eta-backup`，为未加密的本机回退副本；不导出到公共目录。全量恢复启动阶段仍需校验并移动数据，耗时与私有文件大小有关；没有以小数据测试推断超大 Linux 环境能即时恢复。

## 格式与范围

| 格式 | 内容 | 恢复方式 |
| --- | --- | --- |
| 完整迁移包 `.eta-backup` | 会话、会议室、记忆、自学习、计划、统计、配置、凭据和应用私有文件 | 替换应用内数据，重启完成 |
| 可选数据 `.json` | 模型配置、会话与角色、分层记忆，至少选一类 | 仅替换选中类别，未选类别保留 |

JSON schema 8 新增明确的内容清单，旧 schema 1–7 继续按完整逻辑数据导入。选中“会话与角色”包含消息、分支、来源、检查点与角色资料；“分层记忆”包含作用域 Markdown 和结构化条目。JSON 不包含会议室、自学习规则/历史、完整应用设置或工作区文件。

两种格式都可以加密；加密 JSON 使用 `.eta-backup` 后缀，读取时按容器和解密内容识别。外部项目目录文件、Android/ColorOS 权限、系统 Root 授权和 Android Keystore 私钥不会凭备份直接迁移。凭据以可迁移数据重新写入目标设备加密存储，设备密钥不跨机复制。

## 自动备份

- 用户通过系统目录选择器授权目标目录，支持每 1–30 天、0–23 点、保留最近 1–30 份、仅充电时执行、格式/内容和可选密码。
- WorkManager 每日检查本地日期是否到期；手动“立即备份一次”成功会更新起算日期，避免原周期锚点使下次任务额外跳过一个间隔。夏令时与延迟执行有回归。
- 备份、恢复和记忆整理使用共同互斥门；执行前检查前台/Runtime 任务。忙碌或暂时失败进行有界重试。Android/ColorOS 可推迟后台执行，不承诺精确定点。
- 先创建独立 `.part` 文件，完整写入并成功关闭后重命名发布；失败/取消清理自己的临时文档。新备份成功后才清理旧份数，只匹配 Eta 自动备份的严格命名，不删除用户其他文件。
- 旧文件清理失败时保留新备份和成功时间，单独提示清理失败。密码使用 Android Keystore AES-GCM 保存；密钥丢失时要求重新设置，不静默导出明文。

## 成本与运行轨迹

概览提供预估费用、请求次数、已报告 Token、输入缓存命中，支持时间、来源、服务商、实际模型、项目和结果筛选。实际模型包含备用模型及独立子请求；费用与 Token 汇总纳入子 Agent 和上下文压缩，保留独立账目，避免遗漏或重复计算。

活跃轨迹提供最近 13 周日历、运行/Token 切换、连续活跃天数和点击日期过滤；七天趋势使用本地日期。仍遵守现有保留规则：最近 200 条结束运行和所有活跃运行，图表只代表当前保留记录，不声称是终身账单。

运行详情分为摘要、可展开用量、模型尝试、子请求、请求耗时和执行时间线。工具/异常可筛选，事件可打开查看轮次和相对时间。新增首段文字事件，区分响应头、首段文字及请求完成，重试/备用切换各自计算；旧记录缺失的耗时保持未知。

历史费用沿用运行时单价快照，按币种分别合计；没有服务商实际账单和逐 HTTP 用量时不猜费用，显示完整覆盖比例。统计不保存聊天正文、凭据、工具参数和工具结果。逐请求收费对账、预算控制、终身聚合、会议主持用途归因仍属后续 P14 出口，本轮未实现。
