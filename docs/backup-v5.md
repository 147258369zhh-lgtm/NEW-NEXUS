# Eta 完整备份 v5

## 格式

`.eta-backup` 是版本化的完整归档。未加密时，文件内容是一个 ZIP；设置密码后，整个 ZIP 由流式 AES-256-GCM 容器加密。导出界面允许留空密码，生成可供离线工具检查的普通 ZIP。

2026-11-06 导出修复版使用完整归档清单 schema 3，仍可读取 schema 1/2 与旧 JSON。schema 3 新增目录、符号链接和 POSIX 权限元数据；旧版本 Eta 会拒绝这个清单版本，接收设备需先更新到本修复版或更新版本。加密容器仍为原有版本 2，可读取旧的小帧加密文件。

2026-11-07 继续开发后，逻辑 JSON 为 schema 6，包含会话分支、消息来源与创建时设置快照。主库 `eta.db` v26、会话扩展库 `eta_fork.db` v5、项目库 `eta_projects.db` v2；完整归档同时保存实际设置和继承回执。仅逻辑 JSON 不包含项目/文件夹实体，重新关联缺失时保留可见待处理，已放弃的继承不自动重新启用。详见 [分支设置备份合同](P14_BRANCH_SETTINGS_2026-11-07.md)。完整归档清单和加密容器版本不变。

归档包含：

- `eta-backup.json`：旧版逻辑备份合同，用于兼容、统计和校验。
- `data/databases/`：`eta.db`、会议、会话扩展、学习、调度、A2A、通知历史及运行时检查点。
- `data/shared_prefs/` 与 `data/files/datastore/`：设置、MCP/A2A/语音 Token 的 Keystore 密文和 DataStore。
- `data/no_backup/provider_credentials/`：模型账号的 Keystore 密文。
- `data/files/`：聊天/会议产物、Skill、MCP 文件和工作区文件。
- `manifest.json`：格式版本、导出时间、应用版本、根目录状态、分区文件数、记录数、字节数和哈希。

多级会话文件夹的父子关系保存在 `eta_fork.db` v3 的 `parent_id` 中，随完整备份恢复；恢复旧 v1/v2 数据库时按 Room 迁移保留原有根级文件夹。该数据库升级不增加清单版本。仅导入旧版逻辑 JSON 不包含会话扩展分组；完整层级需使用完整归档。

`manifest.json` 中始终存在以下分区，即使当前设备没有对应数据：`core`、`runtime`、`meeting`、`meeting_artifacts`、`conversation_extensions`、`learning`、`tasks`、`a2a`、`notifications`、`mcp_skills`、`settings`、`secrets`、`workspace`。每个分区记录 `present`、`entryCount`、`files`、`bytes`、`recordCount` 和分区哈希；每个归档文件单独记录 SHA-256。

`entries` 和分区文件计数仍统计普通文件；`links` 单独记录链接路径和目标，`directories` 记录包含空目录在内的目录及其权限。支持权限的文件系统同时记录文件权限，不保留 suid/sgid/sticky 或原设备 uid/gid。链接不会被解析成文件内容或递归展开。恢复前检查三类路径不冲突、没有文件或链接作为其他条目的父路径；普通文件区的链接目标限制在归档文件区内，PRoot 发行版内允许保留 guest 的绝对链接。

## 导出

1. 先选择保存位置，再确认密码。密码不写入可保存的页面状态，文件选择器期间页面重建不会自动将加密请求变为明文导出。
2. 检查当前任务，等待已有会话持久化，生成逻辑数据和完整归档。
3. 按不跟随链接的方式流式扫描，最多 200,000 项、256 层目录、8 GiB 解压内容、16 MiB 清单。文件、目录和链接都受遍历预算约束；无法读取或不支持的特殊文件会明确失败，不静默省略。
4. ZIP 使用较快压缩与 256 KiB 缓冲；加密流合并写入为不超过 1 MiB 的帧，避免每次 ZIP 字节写入都重新初始化加密。
5. 归档先写入应用缓存，生成完成后才在 IO 线程打开目标文档，以 256 KiB 缓冲复制；目标关闭成功才报告完成，finally 清理暂存文件。

页面显示任务检查、数据库、对话、文件归档、凭据、清单和最终保存阶段，以及归档文件数、内容大小和复制字节进度。可取消导出，离开页面也会取消；真正的大型 Linux 环境仍可能耗时较长，进度信息用来区分正在工作与卡住。

可选数据 JSON 导出同样会回传逐表和消息分页进度。保存到系统文档提供器时优先使用截断写模式，并在提供器不支持该模式时回退到兼容写模式。自动备份如果因为关机、离线或约束未满足而错过计划时间，会在下次同步时立即补跑一次；大备份使用 `dataSync` 前台 Worker，避免在普通后台执行窗口结束时被系统提前终止。

准备阶段失败或取消不覆盖已有目标；系统选择器可能已创建空文件。最终文档复制没有事务保证，取消、存储不足或文档提供方失败可能留下部分文件，需要重新导出。同步的文档提供方若不响应线程中断，取消也可能延迟。此机制不是整个文件系统的原子快照。

## 导入

旧版 JSON 仍走原有事务导入。完整归档会依次执行：

1. 解压到临时目录，并限制条目数、单文件大小和解压总量。
2. 拒绝绝对路径、`..`、重复条目、清单外文件和损坏哈希。
3. 校验逻辑 JSON、数据库文件、分区计数和整体清单。
4. 在当前数据目录之外创建导入前完整安全快照。
5. 把校验后的数据放入独立暂存目录；当前 Room 和 DataStore 保持不动。
6. 用户重启 Eta 后，在 Application 初始化数据库和 DataStore 之前，按恢复日志保护的步骤替换数据目录。
7. 替换过程中写入恢复状态；异常或进程中断会从旧目录快照回滚，部分目录尚未移动时不会被删除。

完整归档恢复需要重启是刻意设计：运行中的 SQLite、WAL、DataStore 缓存和 Keystore 存储不能被可靠地原地替换。

schema 3 的链接在解压、哈希和清单校验期间只保留为描述，校验通过且普通文件移动完成后才在启动恢复阶段创建；随后恢复普通文件和目录权限。清理及回滚使用不跟随链接的文件树删除，避免目录环或指向外部的链接引发误删。

## 凭据迁移

模型 OAuth、MCP、A2A 和语音凭据的原始 Keystore 密文会进入归档，回滚快照也包含这些密文。Android Keystore 的非导出硬件密钥无法随文件迁移，因此导出时还会生成一份可迁移凭据载荷：它只存在于备份 ZIP 内，不会从正在使用的数据目录扫描到。完整归档恢复后，Eta 在首次启动时用目标设备的 Keystore 重新加密这些凭据，成功后删除临时载荷。

迁移载荷是明文，仅受整个 `.eta-backup` 容器的保护。导出时必须设置强密码；未加密归档等同于一张完整设备数据与凭据快照，不应发送给其他人。如果旧设备上的某条凭据本身已无法解密，该条会跳过并记录不含凭据内容类型的告警，其余数据仍会完整备份。

自动备份密码由当前安装的 Android Keystore 保护，不进入迁移包。恢复完整归档后会保留自动备份的内容和格式设置，但会关闭旧目录并清除旧密码，避免在新设备上显示一个无法解密的密码；用户重新选择目录并设置密码后即可继续使用。
