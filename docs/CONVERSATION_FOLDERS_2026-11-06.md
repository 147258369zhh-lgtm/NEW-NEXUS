# 多级会话文件夹（第四批）

对应原需求 CV-03。本批在前三批 Runtime、工作区搜索/文件夹导出、备份导出修复的本地修改上继续开发；这些修改均保留，尚未提交或推送。

## 已实现

- 会话文件夹支持最多 8 层。侧栏用嵌套容器展示，包含子文件夹、所属会话和后代会话数量；空文件夹也可见并可管理。
- 文件夹右侧“…”打开管理菜单：新建子文件夹、重命名、整组移动、删除文件夹。移动选择器显示完整路径并支持滚动。
- 移动文件夹保留所有后代和会话归属。选择器禁用自身、后代及会使整个子树超过 8 层的目标，数据库事务再次校验。
- 删除只移除当前文件夹；直接子文件夹和直接会话提升到上一层，归档会话一并保留，后代会话仍属于原后代文件夹。如果提升出现同名冲突，整个操作回滚并显示错误。
- 同父级名称唯一，不同父级可以同名。名称前后去空白，长度 1–80，不能包含路径分隔符或控制字符。冲突不会替换已有文件夹。
- 同步修正文件夹内会话排序：使用持久化的成员顺序，移动和删除提升后追加到目标末尾，不会只按最近活动重新排列。
- 嵌套折叠沿用现有动画、界面状态保存，并补充展开/收起触觉反馈。搜索时自动展开匹配会话的祖先，不改变保存的折叠状态；清除搜索后恢复。
- 文件夹操作等待数据库完成后关闭对话框，保存中防重复点击，失败留在对话框中显示本地化提示。包含简体、繁体和英文资源。

置顶会话仍只出现在置顶区域，归档列表仍按原有归档逻辑显示。

## 数据与备份

`eta_fork.db` 从版本 2 升级到版本 3，新增可空的 `parent_id`，并将全局名称索引替换为父级/名称组合索引。SQLite 对 NULL 的唯一索引语义无法限制根级同名，因此根级名称检查也在同一个 Room 事务中完成。

版本 1/2 的文件夹升级后均为根文件夹，保留 id、名称、顺序、时间及会话/归档数据。重命名重新读取当前数据库行，不会因旧界面快照覆盖最新父级。

完整备份直接包含数据库，父子关系随加密和非加密备份一起导出、校验、暂存及恢复。本批不再增加完整备份清单版本，继续使用第三批的 schema 3；旧版应用不能读取 schema 3 的兼容边界见 `backup-v5.md`。

为避免损坏备份导致侧栏死循环，显示树会处理缺失父级、循环关系，并限制嵌套渲染深度；该显示保护不自动改写原数据库。
