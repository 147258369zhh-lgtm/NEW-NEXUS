# P14 分支设置继承、失败恢复与图搜索

本次补齐普通/角色会话分支在创建时继承项目绑定、会话文件夹与独立上下文窗口。继承后仍为独立会话，原会话之后改设置不会同步到分支。模型与角色沿用此前分支机制；归档、置顶、运行状态、草稿和排队消息不继承。对应 P14.4/P14.5，并补 P16 的新增数据覆盖。

## 保存与恢复

- `eta.db` v25→v26 新增 `conversation_branch_setups`。创建时冻结的设置快照与分支、消息、检查点在原串行事务内提交，保存失败不创建半个分支。
- `eta_fork.db` v4→v5、`eta_projects.db` v1→v2 分别新增 `branch_setup_receipts`。目标库的实际设置与回执同事务提交，再由主库确认全部阶段完成。
- 三个数据库各自提交，不能宣称跨库原子事务。目标阶段完成后即使核心确认失败、进程退出或用户手动修改，重试也跳过已有回执，不覆盖已经生效的设置。
- 执行期间固定主库事务，串行化分支核心删除/逻辑导入。核心删除成功后才清理扩展、归档事件、项目绑定与回执，继承与清理共享互斥，不在删除期间复活配置。
- 启动恢复对每条待处理记录尝试一次；之后由页面重试或执行前检查补齐，不无限后台循环。普通 UI 发送与 Runtime 执行均检查继承状态，失败先结束本次请求，尚未调用模型、工具或接管屏幕。
- 文件夹/项目阶段不可用时保留分支和已完成阶段，图内提供“重试”和“使用当前设置”。后者只放弃尚未应用的继承，保留已应用或手动选择的部分；用户须在确认弹窗中看清这一行为。阶段码表示失败发生在哪一阶段，不把所有存储异常断言为文件夹已删除。
- 老分支没有创建时快照，不追溯猜测原设置。导入后设置恢复失败不会阻止加载已经提交的聊天数据；执行检查仍阻止未就绪分支发起任务。

## 备份合同

逻辑 JSON schema 为 v6，新增流式 `branchSetups` section，先检查所属分支、重复 ID、上下文范围、完成状态与阶段码，再替换数据。旧 v1–v5 合同仍可导入；旧分支不自动获得设置快照。

逻辑 JSON 不包含项目库或文件夹库，不能创建它们的实体。普通继承快照导入时换新代次并重新关联，目标依赖缺失时显示待处理；同设备旧回执不能跳过新一轮恢复。已经明确选择“使用当前设置”的记录保留该决定，导入不会重新启用被放弃的继承。完整归档保存三个库、回执及实际配置，恢复后完成或部分完成的阶段不重置用户后续修改。

完整归档清单仍为 schema 3，加密容器仍为 v2；不能把逻辑 JSON 的 v6 写成整个归档格式升级。

## 图与 UI

分支图增加标题搜索，忽略大小写并保留匹配节点的真实祖先和层级；搜索时折叠不隐藏命中节点。缺失父节点和循环仍显示诊断，不改造父关系。运行记录按会话预分组并排序，避免每个节点重复遍历全部运行。

继续使用 Miuix 卡片、正文/辅助字体、确认弹窗和现有操作行。继承中/待处理使用次级文本色，失败才使用错误色；忙时禁用冲突操作。英文、简体、繁体资源同步。大字体、手势和 ColorOS 实际视觉效果由设备验收补齐。

## 自动验证与剩余

新增真实数据库回归涵盖冻结设置、源归档/置顶隔离、核心确认失败后重启补写、用户修改不被重置、依赖消失、放弃继承、并发幂等、删除不复活、老分支独立，以及三个旧版库的显式迁移。逻辑新旧备份、损坏快照拒绝、完整归档恢复和 Runtime 执行前阻断均有回归。全量验证结果登记在 [继续开发记录](DEVELOPMENT_CONTINUATION_2026-11-07.md)。

会议分叉语义、超大历史前缀/分块复制、更完整的图布局、P14 统计的会议聚合/逐 HTTP 收据/预算/长期趋势仍未完成。这次完成多个子能力，不计作完整 P14 或两个原批次。原 16 批、每两个完整批次导出桌面安装包的节点继续保持；版本仍为 4.7.0 / 2026110707，源码备份仍为 2/3。
