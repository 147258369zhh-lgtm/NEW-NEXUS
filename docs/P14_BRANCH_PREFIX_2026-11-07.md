# P14 分支历史前缀读取与角色修订

原实现先读取来源会话全部消息，再裁剪到分叉点。早期分支也会读取之后的巨大正文、附件或数万条消息，触发与本次复制无关的内存/数量限制。本轮改为只读取真实分叉点之前的持久消息。

## 实现

- 先读分叉点的 ID、类型与 sort_index，不提前装载正文、图片或工具参数。目标不存在或不是用户/助手消息时立即停止。
- 助手分叉点通过数据库查询核对下一个用户消息之前是否还有助手正文、工具或工具摘要；有后续块时拒绝中间回复，即使 UI 分页没有加载这些后续记录也不能漏检。
- 从第一条到目标条按唯一 sort_index 游标分页，不再用不断增大的 OFFSET。保留空洞和原真实排序位置，读到目标立即停止，不读取下一轮用户正文。
- 数量与字符预算仅约束实际复制前缀。原会话总量超过 32,000 条、分叉点之后含超过 16 Mi 字符的正文，不再阻止小前缀分叉。实际前缀仍受原有 32,000 条/16 Mi 字符单位保护；更大前缀的持久分块复制仍未完成。
- 已验证前缀从 journal 的第一条用户记录开始按 ID 对齐；无 ID 的旧记录继续核对正文。不因没有读取后续用户消息而将精确历史误判为重建；包含摘要、无法对齐或缺原文时继续明确重建，未闭合工具批次拒绝。
- 先裁剪 journal 再投影角色修订。未来修订不参与过去分支；用户分叉点也使用当前选择的修订正文，并保留“已有工具结果来自原请求”的解释。修订解释增加行数不再导致完整工具历史被误丢弃。
- 原串行保存、源状态变更检查、设置快照与回执机制保留。复制不执行模型/工具；读取与计算仍在后台，分支创建阶段可取消。超限、中间回复、源消息变化和未闭合工具分别显示三语具体原因。

## 验证范围

新增真实 Room 测试包括：33,002 条来源中复制早期两条、实际尾部超限拒绝、300 条带排序空洞的多页前缀、同轮后续正文/工具拒绝、缺失和工具分叉点、旧无 ID 对齐与闭合工具、新身份误配拒绝、未来角色修订隔离、用户修订正文及解释保留、摘要未来内容不泄漏、分叉点后 17 Mi 字符正文不参与预算。

33,002 条/17 Mi 字符为正确性工作负载，不能等同于 OPPO 真机速度、峰值内存或耗电测量。全量与 Lint 结果登记在 [继续开发记录](DEVELOPMENT_CONTINUATION_2026-11-07.md)。

P14 其余未完成项保持：超过当前预算的前缀分块写入、会议分叉、进一步图布局，以及统计成员/整轮/逐 HTTP 收据/预算/长期趋势。没有因此将 P14 标为整批完成；原 16 批与双批桌面安装包节点保持，源码备份仍 2/3。
