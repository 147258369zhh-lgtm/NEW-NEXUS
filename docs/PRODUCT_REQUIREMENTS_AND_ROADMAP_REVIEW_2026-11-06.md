## 2. 合并后的功能定义与设计判断

### 2.1 语音、后台唤醒与接管期间聊天（原 1、15）

已有流式识别/合成、系统识别适配、默认助理和语音浮窗。源码中 `EtaAssistantOverlayService.startSpeech()` 在 `activeRunId != null` 时拒绝录音，解释了“接管时不能继续说话”的一条直接限制；音频租约也会互相打断，默认录音在熄屏时中断。不能只删除判断就称完成连续对话。

采用以下分工：

1. **低功耗待唤醒层**：本地 KWS（唤醒词检测）与 VAD（人声活动检测），多词配置、试听/测试、灵敏度、误唤醒记录；唤醒后再打开 ASR、主模型和 TTS。先验证现成引擎是否支持用户想要的中文词，不能把仅支持固定词的引擎包装成“任意词”。
2. **持续对话层**：流式文字、分句播报、自动收音、说话打断播报、断线重连、静音与结束会话；耳机、蓝牙、通话中断和音频焦点要统一处理。系统 `SpeechRecognizer` 官方不适合全天持续识别，不能用不断重启 ASR 代替唤醒引擎。
3. **任务控制层**：聊天输入与执行器分开。用户可随时问进度、补充条件、停止；停止优先执行。打断播报不等于取消任务；新条件在安全检查点进入，涉及当前操作冲突时排队并解释。
4. **唯一屏幕操作租约**：同一时刻只有一个任务能点击/输入屏幕。浮窗键盘或用户手动接管时暂挂 GUI 操作；纯后台检索、文件等任务可继续。截图排除自身浮窗，避免“看见自己”循环。
5. **后台与锁屏层**：通过合规前台服务、默认助理等可用接口实现最佳体验；Root 后端可增强恢复与系统操作。需分别验证熄屏唤醒、进程存活、锁屏可执行范围。没有 Root 时不能保证系统强停后自行复活，也不能承诺绕过锁屏授权。

系统 ASR 做“自动检测＋选择已安装引擎＋测试＋云端回退”。小米语音只有在当前设备存在可调用服务，或有公开可用接口时适配；OPPO 上不假设存在小米私有服务。界面名称按检测到的真实服务显示。声纹可做本地注册、删除与可调匹配，作为误唤醒过滤，不能充当解锁、支付或高权限授权凭据。

验收：运行任务时仍能收音和收到回答；语音“停止”能停止下游；补充指令不重复执行；熄屏/后台/通话/蓝牙切换有明确状态；唤醒耗电、误触发和响应延迟用设备测量，不能在规划时预填收益。

### 2.2 多层记忆与易懂的自学习（原 2、16，关联 8、9）

“都记起来”定义为：正常会话历史和普通事件可以持久保留、搜索和恢复；自动提炼出有用信息，但每轮仅取相关的一小部分。**不把全部历史、全部项目和所有录音塞入上下文。** 未启用的全天录音、屏幕录像不属于默认记忆；用户删除的内容不应被摘要或索引再次召回。

| 层级 | 保存什么 | 默认如何用 | 用户如何控制 |
| --- | --- | --- | --- |
| 核心重要记忆 | 用户明确要求牢记的原则、关键偏好、稳定身份信息 | 小容量常驻；预算可见，冲突优先提示 | 置顶、编辑、取消置顶；查看占用 |
| 长期事实/偏好 | 持续有效的习惯、设备、稳定事实 | 按语义、时间、关联项目检索 | 更正、有效期、来源、版本 |
| 项目记忆 | 项目目标、决策、术语、路径、关键资料 | 当前项目优先，跨项目访问有明确归属 | 指定所属项目、重要度、归档 |
| 任务工作状态 | 当前计划、完成步骤、阻塞、待办和恢复点 | 当前运行及其恢复使用 | 查看进度、改条件、结束后归档 |
| 普通情景历史 | 日常聊天、低重要度信息、已完成任务经过 | 冷存档，需要时检索片段；不常驻 | 搜索、按时间浏览、保留策略、删除 |
| 经验与技能 | 复用方法、已验证操作步骤、失败教训 | 命中任务后按需加载 | 候选、测试、启用、禁用、回滚 |

重要度与生命周期是不同维度：长期记忆可以很普通，项目记忆可以很重要。避免给用户制造十几种互相重叠的分类。主界面提供“重要、项目、全部记录”，高级筛选再显示时间、类型、来源和状态。

存储优先复用现有 Room、MEMORY.md、CAS、检索与 pin 机制；建立统一记录 ID、来源消息/run、项目、重要度、时间有效区间、版本、删除状态和检索索引。先做可用的中文全文检索与时间/项目过滤，向量检索是增强项，不强制手机运行独立图数据库。FTS 版本按实际 SQLite/Room 能力选型并实测中文检索。

后台增量整理、去重和冲突处理，避免每句话都额外调用一次大模型。核心明确指令可以直接保存；“从行为推断出来的规则/技能”进入待确认区。学习页面用“待确认、已记住、为什么记住、最近用在哪里、是否有效、撤回”解释，不把 curator、candidate 等内部词暴露给普通用户。禁止把模型自己的猜测当成用户事实。

验收：旧事实更正后能查到来源和历史，但不再作为当前事实注入；切项目不串记忆；普通历史可搜索；删除覆盖摘要/索引/缓存并说明已导出的旧备份无法远程撤回；记忆预算和本轮召回内容可检查；导入导出、失败回滚与迁移完整。

### 2.3 项目文件区、文件管理与输出质量（原 3、10）

区分三个对象：**会话分组文件夹**管理列表，**项目工作目录**管理真实文件，**记忆范围**管理检索归属。允许它们关联，但拖动会话到分组不应悄悄移动物理文件。

每项目绑定应用私有目录或用户选择的 SAF 目录，支持多个会话/会议复用；新任务默认在所属项目创建产物。定义原生文件路径与 SAF URI 的能力差异，不向终端伪造不可用的真实路径。需要暂存时明确同步状态、冲突和失败恢复。

聊天右侧提供文件区，同时保留可见按钮。边缘返回手势优先系统；只在内容区识别横划，并与左侧会话导航、消息横向滚动/代码块手势协调。紧凑屏用抽屉/独立页，宽屏可并排，文件区不永久挤压聊天。

文件区包括搜索、排序、预览、重命名、移动、删除、导入、系统分享、多选和“在终端打开”。产物按任务呈现文件卡片，显示真实名称、类型、位置、大小、生成状态、预览/分享入口。草稿与最终文件可区分；只对实际存在且写入成功的文件显示完成。

输出混乱要两端解决：提示词约定先给结论、少重复路径、清楚说明文件用途；软件提供文件写入工具、结构化产物登记、稳定目录、重名处理、结果聚合和预览。不能只靠模型自觉，也不能把聊天文本里的任意文件名当作已生成附件。

验收：项目切换不串目录；跨会话找得到同项目产物；文件不存在/权限撤回/磁盘不足有明确状态；SAF 操作可取消；分享 URI 权限正确；备份恢复后绑定失效可重新选择目录。

### 2.4 系统接管与省 token（原 4、8，关联 7、9）

先输出当前真实能力清单，再补工具缺口；每项记录“支持、需授权、仅 Root、需远端、设备不支持”。下面是目标分层，不表示现有版本已全部具备。

| 能力 | 普通模式目标 | Root 增强目标 | 边界/替代 |
| --- | --- | --- | --- |
| 观察屏幕与操作 | 无障碍语义节点、标准动作、屏幕采集授权、OCR/视觉回退 | 可选系统输入/采集后端，按设备检测 | 安全窗口和锁屏不能保证采集；有失败解释 |
| 应用与跨 App 工作 | 包/Intent、深链、分享、可用应用 API、GUI 执行 | 启停、部分系统设置/受限操作的可用后端 | 私有接口按机型适配，避免声称通用 |
| 文件和产物 | 应用目录、SAF、分享导入、可用媒体权限 | 明确授权目录的增强访问 | 作用域、链接、删除与覆盖仍需边界 |
| 命令与开发 | 普通 shell、PRoot、远端终端 | 独立 Root helper、进程与文件增强 | Root 不等于破解硬件密钥或任意应用加密库 |
| 后台任务/语音 | 前台服务、系统调度、健康诊断、默认助理可用路径 | 可选恢复/系统辅助 | 强停、ROM 管理和麦克风限制必须实测 |
| 网络与远端工具 | HTTP、MCP、A2A、局域网授权、远端宿主 | 按需增强网络诊断 | tsnet/隧道为可选传输，不自动有公网入口 |
| 社交与通知 | 官方 API、连接器、通知读取/可用直接回复 | 可选 GUI/系统辅助 | 通知回复不等于完整账号 API |

观察优先级：可用 API/Intent → 无障碍语义与屏幕结构 → 局部 OCR → 局部截图 → 大模型视觉兜底。动作后等稳定事件并验证结果；缓存按窗口/页面变化失效，不能只相信旧节点坐标。截图裁剪要保留坐标变换，错误/敏感窗口应停止或降级，不猜点击。

其他节省方式：工具 schema 按需发现、长结果存文件并按引用读取、增量上下文、重复观察合并、循环检测、子 Agent 总预算、合理模型路由。记录任务成功率、视觉调用次数、输入/输出 token、总延迟、失败恢复与耗电，对固定任务做前后对比。没有实测前不承诺节省百分比；低 token 但更易失败不算优化成功。

### 2.5 Agent 自建定时任务（原 5）

复用现有持久任务引擎，补齐 Agent 自然语言创建、查询、修改、暂停、恢复、取消。支持一次性/周期、时区、目标会话/会议/A2A、项目、输出位置、模型/工具范围、预算、超时和结果通知。用户说“每天九点整理文件”时应生成一张可查看、可编辑、可撤销的任务卡，并用自然语言解释下一次运行时间。

明确授权且范围明确的低风险任务可直接建立并提供撤销，不机械地每步确认；时间、对象或动作含糊时才澄清。计划运行只使用已授予范围，不能用聊天里出现的一句话替其他来源授权。

验收：重复请求不重复建计划；修改有版本；时区/夏令时/重启/错过执行按明确政策处理；不自动补跑多次有副作用动作；等待输入/认证可以跳回原任务；普通周期执行与确需准点的任务分开调度，系统不授予精确闹钟等能力时显示实际限制。锁屏中需要解锁的 GUI 工作进入等待状态。

### 2.6 会议、会话与上下文治理（原 6、12A、13）

会议与会话共享消息主体、输入草稿、菜单规范；补齐会议置顶/取消置顶、归档/恢复、重命名、搜索、导出与文件夹移动。分组使用带类型的实体 ID，避免同 ID 的会议与普通会话碰撞。长按拖动进文件夹，支持悬停展开、滚动、目标高亮和撤销；菜单“移动到”作为同等可用入口。运行中移动不得丢失控制入口。

上下文圆圈保留占用概览；长按打开本会话设置，普通菜单也能进入。默认继承模型配置，支持恢复默认。分别显示“模型最大窗口、当前会话使用上限、为输出/工具/安全保留、已用及估算状态”。覆盖值不能超过模型实际能力。会议可设置房间策略，各成员按自己的模型与上下文独立计算，不能把全房间粗暴统一成最小模型窗口。

上下文检测采用 provider usage、已知模型元数据/用户配置和模型适配估算。API 返回 token 用量不代表 API 能自动返回最大窗口；未知时明确估算并允许校正，不能假装准确探测。现有字符估算需要按模型/中文语料校准。

压缩新增独立模型/供应商选择、手选范围、任务/项目重点保留、预览和耗时阶段。压缩模型也必须容纳分块；原始 transcript 保留。范围按完整消息组和 tool-call/result 配对调整，固定系统规则、待完成工具调用和必要近期状态受保护。

慢压缩优先改为增量覆盖、摘要缓存、减少不必要多级总结、受控并发分块、合理超时/取消；大并发不应压垮移动端或 provider。成功后原子提交，失败/取消保持原上下文，编辑或新消息到来后验证摘要版本，防止覆盖更新。总结模型不可用时保留原内容并允许重试；未经用户配置不自动把内容转发到另一供应商。

验收：每会话/会议覆盖互不污染；范围可解释；压缩不丢工具配对、关键约束和最新输入；在同语料/模型/网络条件下比较延迟、成本、质量。不能保证所有远端模型都即时完成。

### 2.7 MCP、Skills、终端与小模型（原 7、9，关联 8、16）

已有 MCP 添加、刷新与 Token 更新，已有 Skill ZIP 安装、冲突处理、安装锁及回滚；在此基础上补管理闭环，不重写已验证的解包器。

MCP：连接生命周期、协议协商、认证/重新认证、工具/资源/提示模板、测试调试、取消、输入校验、超时、结果大小限制、按 Profile 授权、配置导入导出、版本变化和脱敏诊断。OAuth 等按服务器/协议实际支持实现，不能假设全部服务器都提供；固定协议基线并覆盖旧服务器兼容。

Skills：浏览完整资源、编辑 SKILL.md/资源、格式校验、未保存保护、可控测试、包导出、来源/hash/版本、更新差异、本地修改冲突、回滚和经验候选晋升。自动加载入口先展示简要描述，命中后再读取正文/资源，减少无关 token。

| 复用层 | 移动端策略 |
| --- | --- |
| MCP 协议、远程服务、Skill 文本和资源格式 | 优先复用；校验协议、路径、权限和大小 |
| Android 原生能运行的工具 | 应用内适配，支持生命周期和取消 |
| ARM64 Linux 工具、Node/Python 等依赖 | 可选 PRoot 环境，逐包验证系统调用、内存、后台与安装成本 |
| 桌面二进制、浏览器自动化、重型数据库/模型 | 远端 MCP/A2A/工具宿主连接，不能承诺原样跑在 Android |

终端环境安装、更新、取消、失败恢复、会话/进程、后台任务、项目目录联动和 Root/PRoot 区分继续纳入原有任务。

小模型保留“待定/可选模块”：先做本地或用户自托管服务的配置、能力检测、资源预算、简单分类/抽取/路由、主模型不可用时的明确降级。再按设备测量决定是否加入端侧推理引擎。掉线时不悄悄让小模型重复已可能执行的写入/付款/发消息任务；不保证小模型替代完整规划与视觉。通用 NPU 加速不列入主线承诺。

### 2.8 社交连接器（原 11）

目标是把消息渠道接入同一 Runtime，而不是为每个平台另造 Agent。统一消息/附件、会话映射、身份和授权、去重、重连、限流、停止、运行状态与结果文件。外部群聊/私聊不能默认继承手机本地主人的全部权限；用户可配置哪些身份能用哪些能力。

| 路线 | 计划 | 条件与限制 |
| --- | --- | --- |
| QQ 官方独立机器人 | 第一优先，依据 QQ 开放平台及官方示例，支持可用的消息/附件能力 | 开放平台应用、权限、发布范围和会话能力以实际账号为准 |
| 个人 QQ 桥接 | 调研 NapCat/OneBot 类服务端/电脑桥接，Eta 作为客户端 | 需要可用宿主、账号和协议版本；不是把桌面 NTQQ 直接装进手机；账号稳定性不可保证 |
| 其他有官方 API 的渠道 | 复用统一连接器接口，根据实际需求增加适配 | 按平台文档与测试账号逐项验收，不承诺一次覆盖所有社交软件 |
| 个人微信等 | 区分官方能力、通知直接回复、GUI 操作与第三方桥接，先验证一条可用链路 | 没有公开通用个人账号接口时不能承诺完整收发/历史同步；桌面桥接与应用版本可能变化 |

本阶段实现统一连接器与 QQ 官方主线，个人 QQ 列为条件适配工作，不因缺电脑宿主阻塞其他功能；个人微信的具体接入方式等可行性证据齐全再定。不自动部署外部网关或使用真实账号发测试消息。

### 无障碍稳定性专门处理（原 14）

现有 `AgentAccessibilityKeeper` 有恢复基础，但部分持久保护走 system_server Hook；要将该路径从核心依赖中分离。普通模式做服务启用/实际连接/心跳区分、断开时间与原因、ROM 管理指引、任务暂停/恢复入口；不能“开关显示开着”就判断服务可用。

Root 模式建立独立可选恢复后端：检测 helper、授权和实际服务状态，受控重绑/恢复，退避与次数上限；修改服务列表要合并其他已启用服务，不能覆盖。用户主动暂停、关闭或撤销授权时尊重其选择，不形成无限拉起循环。Root 丢失明确降级。验收包括熄屏、长任务、内存压力、升级、重启、主动停用和其他无障碍服务共存。

## 5. 全软件设计规范与审查范围（原 12B，贯穿全部批次）

以当前组件和主题 token 为基础先盘点，不另外引入一套与现有界面冲突的视觉体系。以下是验收规则，具体尺寸从现有设计提取后统一，不在规划中随意重定所有字号。

| 维度 | 规则 |
| --- | --- |
| 信息架构 | 聊天聚焦对话与当前任务；项目/文件/记忆/连接器各有固定入口；高级参数逐级展开，不把所有设置堆在输入栏 |
| 组件与布局 | 卡片、列表、开关、输入、菜单、底部面板复用现有组件；间距/圆角/对齐统一；主要操作位置稳定，关键按钮不随状态乱跳 |
| 字体与内容 | 标题/正文/辅助信息有清楚层级；遵循字体缩放，避免固定高度截字；数字/状态/代码各有合适排版，中文不挤成窄列 |
| 颜色与材质 | 浅色/深色/纯黑一致；语义色不只靠颜色传达；保留 Mica 风格并提供模糊/性能降级，优先文字可读性 |
| 手势与可发现性 | 拖动、滑动、长按均有按钮或菜单入口；避免系统边缘返回冲突；移动/归档等可撤销 |
| 状态完整性 | 加载有阶段、长任务能取消；空态给下一步；断网/权限不足/部分成功/取消/恢复均有真实状态，不用无限转圈掩盖失败 |
| 可访问性 | 主要点击区域至少 48dp；TalkBack 标签、焦点顺序、足够对比、减少动画；大字体下仍能完成核心流程 |
| 性能与反馈 | 长列表懒加载；拖动/键盘/滚动不阻塞主线程；动效轻且连续，耗时 IO/索引/压缩不在 UI 线程运行 |

逐页审查清单：普通聊天、会议/成员详情、侧栏/分组/归档/搜索、模型与上下文/压缩、项目/文件/预览/分享、语音浮窗/唤醒设置、记忆/学习、任务中心/待处理、MCP/Skills、终端/环境、小模型、A2A/配对/传输、社交连接器、统计/轨迹/分支、备份恢复、权限健康、通用设置、Classic/Omni/灵屏/流体云。

每页核对浅/深/纯黑、360/412/600dp、普通/大字体、键盘显示、横竖屏和系统栏。截图/预览与自动布局检查先做，最终设备手感由用户确认；16/17 的系统行为分别记录。每批改到的页当批审查，第十五批做全页一致性收口。
